# MGinbon クライアント進捗共有設計 1

作成日: 2026-09-18  
対象: みくに出版向け読み取り専用共有URL

## 1. 方針

外注先にはSBWorkアカウントを発行せず、外注作業の担当先・状態・日付・点数は社内担当者が入力する。
クライアントのみくに出版には、MGinbon管理台帳から安全な公開項目だけを抽出した読み取り専用URLを
発行し、進捗を随時確認できるようにする。

既存進行管理表の共有URLが持つ次の操作を継承する。

- ランダムな共有トークンを発行
- 認証なしで閲覧可能
- 編集操作なし
- URLコピー
- 印刷
- 管理者が即時無効化

## 2. 既存機能の調査結果

既存`progress_sheets`は64文字の一意な`share_token`を持ち、公開ルートから読み取り専用表を表示する。
発行者は同じトークンを再利用でき、無効化時はトークンをNULLにして旧URLを404にする。

現在の共有レスポンスには、担当者名、外注先名、セルメモ、メモ記入者等も含まれる。社内用進行表を
そのまま共有する設計なので、MGinbonのクライアント共有には公開範囲が広すぎる。

## 3. MGinbon共有ビュー

MGinbonでは管理台帳そのものを外部公開せず、年度ごとのクライアント共有設定から専用ビューを生成する。

```text
┌─ 2026年度 銀本制作進捗（閲覧専用）────────────────────────────────────┐
│ 最終更新: 2026/04/14 16:20                                             │
│ 学校 [____________]  媒体 [すべて▼]  科目 [すべて▼]  状態 [すべて▼] │
├────┬────────────┬──────┬────┬────┬────┬────┤
│コード│学校          │媒体    │科目│初校│再校│三校│校了│
├────┼────────────┼──────┼────┼────┼────┼────┤
│238 │学校A          │問題    │国語│完了│進行中│未着手│    │
│238 │学校A          │問題    │算数│完了│進行中│未着手│    │
└────┴────────────┴──────┴────┴────┴────┴────┘
```

初期公開候補:

- 年度
- みくにコード等、クライアントと共有済みの識別コード
- 学校名
- 媒体
- 科目
- 工程段階
- 未着手／担当済み／進行中／完了
- 出稿日、戻り日、校了日等のクライアント共有対象日
- 最終更新日時

非公開項目（確定）:

- 社員名
- 外注先名
- 個人別作業時間・カレンダーEvent
- 社内メモ、差し戻し理由、変更履歴
- 外注点数・単価・金額
- 内部Assignment ID、Event ID、ユーザーID
- FileMaker取込元値・取込警告

表示項目は共有設定のallowlistで管理し、管理台帳レスポンスからフロント側で隠すだけにしない。
公開用コントローラが許可項目だけを取得・整形する。

## 4. トークンと失効

候補テーブル: `mginbon_share_links`

- `id`
- `mginbon_project_id`
- `token_hash`（平文トークンをDBへ恒久保存しない方式を優先）
- `name`（例: みくに出版 2026年度進捗）
- `audience_type`（client）
- `view_config`（公開列・フィルター。サーバー側allowlistで検証）
- `expires_at`（nullable）
- `revoked_at`（nullable）
- `last_accessed_at`（nullable）
- `created_by`
- timestamps

既存機能との操作互換を保ちつつ、MGinbonでは次を追加する。

- 再発行で旧URLを失効可能
- 任意の有効期限
- 最終アクセス日時
- 発行者・失効者の監査履歴
- 年度終了時の一括失効

アクセスログへトークン全文を出さない。URLはHTTPS前提とし、検索エンジン向けには
`noindex, nofollow`を返す。

## 5. 権限

- 発行・再発行・無効化: SuperAdmin、Admin、Leader、Clerk、Coordinator
- 社内プレビュー: 上記権限
- 外部閲覧: 有効なトークンを持つ者。編集APIは存在させない
- 外注先: 共有URLの対象にせず、SBWorkへの直接入力も初期実装では行わない

## 6. 更新の反映

共有画面はコピーしたスナップショットではなくMGinbon正規データを読み取るため、次の更新が反映される。

```text
社内担当者が進行表で登録
  → Assignment／Event／MGinbon工程を更新
  → 管理台帳へ反映
  → 共有ビューへ公開可能項目だけ反映
```

キャッシュする場合も短時間とし、完了・出稿等の重要更新後に対象年度の共有キャッシュを無効化する。

## 7. 確認済み事項

みくに出版向け共有画面には社員名、校正者名、外注先名を表示しない。学校・媒体・科目・工程状態と、
クライアント共有対象の日付を中心に公開する。
