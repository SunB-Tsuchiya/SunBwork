# MGinbon プロジェクト起点・担当者連動 計画1

作成日: 2026-09-26
状態: 調査・設計完了、実装確認待ち

## 1. 結論

銀本年度プロジェクトは、SBWorkのプロジェクトジョブへ必ず接続してから進行管理を開始する。担当者・外注先の正本は年度別値一覧ではなく、接続したプロジェクトジョブの所属者とする。

```text
SBWork プロジェクトジョブ（必須）
├─ リーダー・副リーダー
├─ project_team_members（社員・正式登録した仮メンバー）
├─ project_job_subcontractors（案件で使う外注先・新設）
└─ MGinbon年度プロジェクト（1年度から接続）
   ├─ 年度別担当区分マスター
   ├─ LIST・詳細・出稿表
   └─ JobBox・カレンダー・作業実績
```

## 2. 現状調査で判明したこと

- 社員は `project_team_members` により案件単位で登録済み。
- 外注先には案件所属テーブルがなく、現在の `ProjectJobAssigneeOptions` はログイン担当者が管理する外注先を全件返している。
- 同サービスは、案件へ登録されていないghost userも所有者単位で全件候補へ加えている。
- ghost userはテストログイン用で、1人限定・14日失効のため実務上の任意担当者には使わない。
- MGinbon年度の `project_job_id` はnullableで、現在は未接続でもLISTや進行表を開ける。
- 接続解除にも進行データ存在時の制限がない。

## 3. 追加する案件外注先所属

本体DBに `project_job_subcontractors` を新設する。

- `id`
- `project_job_id` FK、案件削除でcascade
- `subcontractor_id` FK、外注先削除でcascade
- `created_by`
- timestamps
- unique: `project_job_id + subcontractor_id`

`ProjectJob::subcontractors()` と `Subcontractor::projectJobs()` を追加する。案件作成・編集・詳細の「チーム」領域で、社員メンバーと案件外注先を並べて管理する。

候補に追加できる外注先は同じ会社に属する登録済み外注先だけ。外注先マスターにない名称を使う場合は、先に外注先マスターへ登録してから案件へ追加する。

## 4. 担当候補の正本と順序

共通サービス `ProjectJobAssigneeOptions` を次の仕様へ変更する。

1. 案件リーダー・副リーダー
2. `project_team_members` の社員
3. `project_job_subcontractors` の外注先

ログイン担当者が管理するだけで案件未登録の外注先と、案件未登録のghost userは返さない。重複IDは除外する。

候補から外れた人に既存割当がある場合、過去表示と実績は保持するが、新規割当候補には出さない。「案件メンバーから外れています」と警告表示する。

## 5. 年度別マスターの役割

担当者系5一覧は、人名の正本ではなく案件所属者への年度別工程区分とする。

- チェック担当者
- 作業担当 作図・文字入力
- 作業担当 組版
- 原本scan担当
- 文字校正担当

各値一覧行は次のどれかを持つ。

- `linked_user_id`
- `linked_subcontractor_id`
- どちらもnullの表示専用・旧値・任意文字列

同じ人・外注先を複数区分へ登録できる。正式担当候補は「案件所属候補」と「年度区分リンク」の積集合にする。

区分リンクが0件の工程は移行期間として案件所属者全員を表示し、「担当区分未設定」と明示する。1件以上設定された区分はリンク済み候補だけを表示する。

値一覧への任意文字列追加は維持するが、リンクなし行は帳票表示・FileMaker旧値保持に限定し、JobBox担当として保存できない。

## 6. 銀本年度とプロジェクトジョブの必須接続

### 新年度

- 年度取込の前に、既存プロジェクトジョブを選ぶか銀本専用案件を作成する。
- `project_job_id` が決まらない状態では年度取込を確定できない。
- 専用案件作成時は作成者をリーダー兼チームメンバーとして登録する。

### 既存の未接続年度

- データは削除しない。
- LISTは接続案内だけを表示し、担当設定・進行更新・帳票値更新を停止する。
- 「既存案件へ接続」「銀本専用案件を作成」の2経路を提供する。

### 接続解除・変更

- 制作単位だけで工程・担当・日付が未作成なら変更可能。
- 工程参加者、作業パッケージ、JobBox割当、手入力日付のいずれかがあれば解除・別案件への変更を禁止する。
- 誤接続救済は専用移行処理として監査ログ付きで別途扱う。

DBのnullableは既存データ移行のため当面維持し、アプリ層で必須化する。全既存年度の接続完了後にDB NOT NULL化を再検討する。

## 7. 年度コピー時の担当リンク

- 文字列、順番、有効状態、区分をコピーする。
- コピー元の `linked_user_id` / `linked_subcontractor_id` がコピー先プロジェクトジョブにも所属する場合だけリンクを維持する。
- コピー先案件に所属しないリンクはnullへ落とし、「未接続候補」として一覧上で警告する。
- コピー操作だけでコピー先プロジェクトジョブへ人・外注先を自動追加しない。

## 8. UI

### プロジェクトジョブ

- 案件作成・編集・詳細に「社員メンバー」「外注先」を表示。
- 外注先選択は同会社の外注先マスターから複数選択。
- 未登録外注先は外注先マスター新規登録へ案内し、登録後に案件へ追加。

### 値一覧

- 担当者系一覧では、自由文字入力に加え「案件メンバー／案件外注先から追加」を提供。
- 各行に社員・外注・表示専用の種別バッジを表示。
- 案件から外れたリンクは警告し、再対応付けまたは表示専用化を選べる。
- 削除は無効化。通常候補から消し、削除済み表示から復元可能。

### LIST・詳細・出稿表

- すべて同じ年度・同じ接続案件・同じ共通候補サービスを利用。
- 工程コードから担当区分コードを決定し、その候補だけを表示。
- 保存APIでも同じ候補集合を検証し、画面改変による範囲外割当を拒否。

## 9. 実装フェーズ

### Phase A: プロジェクト基盤

- `project_job_subcontractors` migration/model relations
- 案件作成・編集・詳細の外注先登録UI/API
- `ProjectJobAssigneeOptions` を案件所属限定へ変更
- 既存利用箇所の回帰テスト

### Phase B: 銀本接続必須化

- 年度取込時の案件選択／専用案件作成
- 未接続年度ガード
- 接続解除・変更の使用中判定
- 既存未接続年度の救済画面

### Phase C: 年度担当区分

- 値一覧行の社員・外注リンク編集
- 案件所属との整合検証
- 年度コピー時のリンク再判定と警告

### Phase D: 実画面接続

- 工程コードと担当区分の対応サービス
- LIST・詳細・出稿表の候補統一
- JobBox保存側の範囲検証
- 13値一覧の非担当項目接続は `MGINBON_VALUE_LINK_PLAN1.md` に従う

## 11. 検証

- 案件Aのメンバー・外注先が案件Bへ混ざらない。
- 管理中でも案件未登録の外注先は候補へ出ない。
- 案件未登録ghost userは候補へ出ない。
- 年度未接続では進行更新を拒否する。
- 案件から外した既存担当の履歴・実績は消えない。
- 区分設定後は工程別候補が絞られ、未設定時の移行フォールバックも動く。
- フロントと保存APIの候補判定が一致する。
- 年度コピーでコピー先案件にいない担当リンクを自動継承しない。
