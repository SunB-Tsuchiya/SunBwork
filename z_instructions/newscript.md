# 前提
- レイアウトや画面の見た目の方向性は既に把握済みなので、UIデザイン提案は最小限でよいです。
- 重点は、機能仕様、例外仕様、入力仕様、命名規則、処理フロー、技術設計、データ設計、エラーハンドリング、ログ、テスト、運用制約です。

- 不明点があっても、まず実務的に妥当な前提を置いて設計案を出してください。その上で「要確認事項」を最後にまとめてください。

# 背景
社内に大量の写真ファイルがあり、別途CSVまたはExcelの一覧表があります。
一覧表には主に以下の情報があります。
- ID
- タイトル

画像ファイル名は現在、IDのみで構成されています。
例:
- 001.jpg
- 002.tiff
- 003.jpeg

一覧表には例えば以下のように入っています。
- 001;北信越の特急あさま_車窓から

このとき、アプリの実行により画像ファイル名を次のように変更したいです。
- 001.jpg → 001_北信越の特急あさま_車窓から.jpg

拡張子は元のまま保持してください。
jpg以外に、jpeg, png, tif, tiff, webp なども対象候補です。

# 想定利用者
- PC操作には慣れているが、CUIやスクリプト実行には慣れていない社内ユーザー
- できるだけ迷わず、安全に使えることが重要
- 誤操作時の被害を減らしたい
- 実行前に結果を確認できることが重要

# 想定環境
- 社内には会員制Webサイトがある
- そのサイト内に本機能の実行ページを設ける案が有力
- サーバーはさくらのレンタルサーバー
- Pythonは使える
- Node.js利用可能性はあるが、レンタルサーバーなので常駐や負荷制約には配慮が必要
- 実際にリネーム対象となる画像フォルダはユーザーのローカルPC上にある
- サーバーに大量画像をアップロードさせる方式は、UX・通信量・運用負荷の観点から極力避けたい
