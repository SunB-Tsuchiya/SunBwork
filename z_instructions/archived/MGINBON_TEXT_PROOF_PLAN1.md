# MGinbon 文字校正一覧 計画1

更新日: 2026-09-29

## 目的

FileMakerの「文字校正」に相当する画面を、銀本制作進行の専用ヘッダーと既存の正規化データで実装する。
学校・媒体・教科別の校正工程を一覧し、ページ数を画面上で入力・保存できるようにする。

## 確定した業務ルール

- 文字校正は新しい工程ではなく、既存データを校正工程中心に再構成した一覧である。
- ページ数は媒体・教科ごとに管理する。
- FileMakerの元項目例は `中学入試::問頁数_国語`、`中学入試::解のみ頁数_国語`。
- 対象媒体は「問題」「解答のみ」「解説解答」「傾向と対策」。
- 「解説解答」と「解答のみ」は別ファイル・別媒体である。
- 「解説解答」はα版だけに存在する。
- 「解答のみ」は原則1ページだが、第二回や一部の学校では媒体自体が存在しない。
- 媒体が存在しない組み合わせは自動生成せず、文字校正一覧でも空欄とする。
- 三校・四校の校正発注日・校正納品日は実運用で使わないため追加しない。
- ページ数はLaravelの文字校正画面から入力できるようにする。
- MyJobの数量は1ジョブ1値で、複数教科登録から教科別ページ数へ逆配分できないため、今回の連動対象外とする。

## データ設計

`mginbon_page_counts` に学校・試験回、教科、ページ区分、ページ数を保存する。

- 媒体の存在有無から入力可否を自動判定せず、4区分×4教科を常に入力可能にする。
- `null` は未入力、0は原則許可せず、正の整数を保存する。
- 媒体の有無は既存の `mginbon_items` を正本とし、例外校や第二回をコードへ固定しない。
- 問題・解答・傾対・解説の入力先は利用者が判断する。自動初期値は設定しない。

## 画面構成

既存の `Coordinator/MGinbon/LedgerIndex.vue` に `text_proof` ビューを追加し、FileMakerに近い横長一覧を専用コンポーネントで描画する。

### 左側

- みくにコード
- 日能研コード
- 日能研分類・学校分類
- 学校名、試験回、α区分
- 存在する媒体と教科
- 銀本掲載、問題原本入稿、メモなど既存項目

### 中央（教科列）

- 入稿日
- 初校・校正、校正発注、校正納品
- 再校校正1、校正発注、校正納品
- 再校校正2、校正発注、校正納品
- 三校・校正
- 四校・校正

既存の工程担当・milestoneを表示し、既存のセル編集方式を可能な範囲で再利用する。三校・四校の未使用日付行は作らない。

### 右側（ページ数）

列は国語・算数・社会・理科、行は次の4区分とする。

- 問題頁数 → 媒体「問題」
- 解答頁数 → 媒体「解答のみ」
- 傾対頁数 → 媒体「傾向と対策」
- 解説頁数 → 媒体「解説解答」

該当媒体・教科が実在するセルだけ編集可能にする。存在しない媒体は無効セルとして表示する。

## 保存API

- ページ数だけを更新する小さなPATCHルートを追加する。
- 対象の `mginbon_item_subjects` が指定年度・表示対象媒体に属することをサーバー側で検証する。
- 値は nullable / integer / min:1 / 現実的な上限で検証する。
- 更新時は `mginbon_change_logs` に変更前後を記録する。
- 成功時は既存のグローバルトーストを利用する。
- ProjectJob未接続年度の更新は既存 `MGinbonProjectAccess` と同じ方針で拒否する。

## FileMaker取込

現行の取込JSONにはページ数フィールドが含まれていないため、初期実装はLaravel画面での手入力を対象とする。
将来、完全修飾フィールド名の一覧またはページ数を含むエクスポートが得られたら、normalizerへ次の形式で追加する。

- `問頁数_{教科}` → 問題
- `解のみ頁数_{教科}` → 解答のみ
- 解説解答・傾向と対策もFileMakerの実フィールド名に従って追加
