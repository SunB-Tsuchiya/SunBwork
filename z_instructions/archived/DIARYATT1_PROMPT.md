# DIARYATT1_PROMPT — 新セッション開始用プロンプト

このプロンプトは、日報添付ファイル改修（フェーズ2）の作業を新しい Claude セッションで再開する際に使用する。

## 経緯サマリー

- 日報で画像添付時にログイン画面へ戻され入力内容が消失する報告があり調査。原因はセッション切れ時の強制フルリロード（フェーズ1で修正済み・ビルド済み）。
- 調査の過程で、日報の添付ファイルが「本文 Quill エディタに直接 `insertEmbed` で埋め込まれるだけで、`attachmentables` ピボットに紐付けられないケースが大半（孤児化）」という設計上の欠陥が判明。
- これを機に、添付ファイルを本文埋め込みから独立させ、一覧＋モーダル閲覧できる方式に変更する（フェーズ2）。

## 作業開始時の手順

1. `DIARYATT_MANAGER1.md` の進捗一覧を確認し、未完了（⬜）のタスクから着手する。
2. 各タスク実施前に対象ファイルを実際に読み、想定通りの実装になっているか（特にフェーズ1で追加した下書き自動保存ロジックと衝突しないか）を確認する。
3. Vue/JS ファイルを変更したら必ず `npm run build` を実行する。
4. 全タスク完了後、CLAUDE.md の「作業完了後」ルールに従い、ChangelogSeeder 追記・CONSOLIDATED ドキュメント更新・PLAN/MANAGER/PROMPT の archived/ 移動を行う。

## 重要な設計判断（変更しないこと）

- 既存日報（過去分）へのデータ移行は行わない。本文に既に埋め込まれた `<img>` はそのままインライン表示を維持する。
- `attachment_ids` の紐付けは、必ずサーバー側で `user_id === Auth::id()` と `status === 'ready'` を検証してから行う（他人のアップロードを紐付けられる脆弱性を作らない）。
- ステージング中（保存前）の添付ファイルは `AttachmentService::attachPivot` を保存時にのみ呼ぶ。アップロード時点（`/api/uploads`）ではピボットを作らない設計を維持する。
