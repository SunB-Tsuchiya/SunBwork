# ワークロード解析・引き継ぎ（統合）

概要

Workload Analyzer と AI ハンドオーバー向けの要点をまとめたドキュメントです。リーダー／管理者向けの解析画面や設定（係数）の扱い、ハンドオーバー時のチェックリストを含みます。

ワークロード解析

- 2026-10-11、情報出版 SuperAdmin 試用の簡易順位・詳細分析から `/schedule/department-work/guide` へ進む導線を追加。新ガイドは短い概要と、対象記録・表示順・点数・評価時の注意を段階的に開く詳細で構成する。工程候補は人・日付・作業区分・種類・案件等でまとめた参考数で、完了数ではない。入力件数は認定記録の数で、分割入力に左右される。暫定点は主に重複除去後の記録時間由来で、査定点にしない。作業区分・入力元フィルタは該当する人を表示するだけで、その人の数値は全記録の合計。旧方式ガイドも概要から詳細へ開く構成に整理し、点数帯を人物評価へ結びつける説明を除いた。点数式・API・他部署の旧分析は変更しない。
- 2026-10-11の情報出版 SuperAdmin 試用では、メニューの旧 `workload-analyzer` 入口を `schedule.department_work.details` へ向け、旧方式は `superadmin.workload_analyzer.archive` に読み取り専用で保全する。旧方式は現DBによる再計算であり、過去点の固定保存ではない。他部署と Admin/Leader の旧入口は試用中そのまま。予定表の「作業実績の内訳」は簡易順位、詳細分析は月／3か月・担当・作業区分・入力元・工程候補・記録日・点数内訳を確認する画面とする。現行の時間点は暫定で、工程候補を完了数と断定しない。
- 2026-10-11の追加調整で、情報出版の簡易順位と詳細分析は `WorkloadAnalysisShell` を使う独立画面とし、予定表と Super Admin の入口は別タブで開く。役割別の `AppLayout` ヘッダー・タブを表示しない。独立画面内の二画面は同じタブで切り替える。旧方式アーカイブは別タブで参照する。
- 試用順位と詳細分析の対象者は `user_employment_settings.ranking_included` / `workload_tracked` を優先する。未設定なら正社員・契約社員を含め、派遣・業務委託を除外する。入力対象外を0点順位に置かず、対象外人数だけ表示する。本人のカレンダーや部署予定の表示範囲はこの判定で変更しない。
- 2026-10-12のローカル試用改修では `WorkloadTrialAnalysis` が、開始・終了時刻を記録した簡易作業も進み・作業種類なしで集計する。未指定の作業種類には標準係数1.0を使う。過去のマイジョブ・依頼ジョブ、仕事の共有予定・会議もJST時間帯に直し、昼休憩を除く。重複する作業同士は等分する。会議・業務外出・顧客訪問が長い作業枠と重なる時間は前者を優先する。作業基本点は10点/時×種類係数。ページ数・サイズ・難易度は点数と人別生産性の比較に使わない。
- 2026-10-20、利用者は現行の合計点・係数を維持したまま、基本点を「作業点（会議・訪問以外）」と「会議・訪問点」に分ける表示を承認。`meeting`、`outing`、`sales_visit` を後者に入れる。残業・案件登録・案件管理は従来の別表示を保つ。分割は重複・休憩を除いた後の点数に行い、二つの表示値の和を基本点に一致させる。日・週・月と人別に内訳を返す。簡易順位は合計点だけを1行で見せ、内訳は名前を押した詳細と詳しい分析に残す。簡易順位と詳しい分析の一部は利用者画面確認済み。週の集計は利用者判断により日曜始まり・土曜終わりとし、週内の日付選択と範囲表示を用いる。期間切り替え中は旧結果を隠して進行表示を出す。週区切り修正 `b0d7e29a8` はさくら反映済み、修正後の画面は未確認。`trial_time_v2` の認定条件やprivate範囲は変更しない。仕事の通常予定を将来どう認定するかは `EVALUATION_SCORE_PLAN1.md` の未決事項。
- 勤務記録の残業と記録済み作業が重なる時間には、最初の3時間を基本点の0.5倍、超過分を0.2倍で追加する。記録のない残業は別表示。案件登録は通常・テンプレート・複製・部署共有・一括・CSVを同じ5点/件とし、過去案件の登録者は移行時のリーダーからの推定として件数を表示する。案件管理はチーム作業が直近14日にある案件の活動日につき0.5点、リーダー1.0／副リーダー0.8、作業メンバー数で最大1.6倍の試験式。追加点は画面でオン・オフ可能。係数は本番の実態を見て調整する。

- 「作業実績の内訳」は期間内の時間記録件数・重複除去後の記録時間・記録者数を示す。同じ作業種類の人別記録時間を比較する。数量は各記録の参考情報に残すが順位・速度比較には用いない。開始・終了のある簡易登録は進みの記入なしでも計上し、未来の日付は計上しない。表示値は部署・案件公開設定によるフィルタ後の値で、非公開の作業を他者の順位へ足さない。現在のWorkloadAnalyzer点とは別物で、評価査定の自動基準にはしない。
- 試用対象者の日報作成・編集画面では、記録された作業時間が通常勤務枠を30分以上下回る場合にだけ非強制の案内を出す。進み・作業種類の空欄は不備として扱わない。勤務形態が未設定ならA日程の7時間30分による概算と表示する。勤務枠外の作業で通常勤務枠の空きを相殺せず、重複・昼休憩は試験分析と同じ方法で除く。未記録分は自動加点しない。
- 人別の作業内訳は2列カードで表示する。積み上げ棒の全幅は表示期間中の最長記録時間を基準とし、色で作業区分を示す。人別カードと部署の作業予定はユーザー一覧で保存した `users.sort_order` 順に並べる。ポイント・同じ作業種類の比較は順位順を保つ。
- 2026-10-27 の試用表示方針: 簡易分析の右欄は、重複・昼休憩控除後の認定時間をジョブ作業、簡易作業、会議・訪問、その他の業務予定へ帰属させ、総時間と区分ごとの時間を示す。重複の優先順位と均等配分は採点用 minute ledger と同じ。役割色と用途色を混同しないよう、役割は名前・絞り込みに残し、従来の作業区分比較は折りたたみの補助表示とする。記録時間は勤務態度や成果の尺度ではない。試用反映・画面確認の状態は `EVALUATION_SCORE_MANAGER1.md` を参照する。
- 同日追加方針: 用途色はカレンダー登録メニューに合わせてジョブ藍、簡易作業ピンク、会議/訪問緑とし、その他を灰色、認定残業を赤とする。認定残業は勤怠申告と記録済み時間の重なる分を用途より優先して表示し、元用途から同分数を引く。残業追加点の日2時間上限は表示する残業時間の上限ではない。5色の合計は総認定時間に一致する。
- 利用者の画面確認後、認定残業の赤が簡易作業のピンクに近く強いとの指摘で、認定残業は黄橙色へ変更する。簡易比較は担当職種別の絞り込みの代わりに、総時間または各用途時間の降順を選べるようにする。棒の長さは総認定時間、右端の値は選んだ区分の時間。旧作業区分比較内の担当絞り込みは残す。試用反映と画面確認は管理ファイルで追う。
- 暫定順位を左、同じ作業種類の記録量比較を右に置く。両グラフの棒色は登録時の担当 `users.assignment_id → assignments.code` を優先し、担当が未分類の Clerk は事務色、Coordinator は進行管理色、Proof Coordinator は校正色とする。下部の人別積み上げ棒は別目的の「実際に記録した作業区分」の色を保持する。ローカル試用では情報出版の営業担当マスターを追加し、架空利用者だけに割り当てる。
- ローカル試用は `PersonalWorkDemoSeeder`。`APP_ENV=local` かつ DB 名 `sunbwork` でのみ動作し、`.invalid` メールの架空ユーザー、`【試用作業】` 案件と自己割当ジョブ、予定だけの人を作る。既存利用者は変更しない。
- `workload-setting?dept=1` は情報出版の作業種別・校数・サイズ・難易度などの独立マスターを管理する画面。`work_item_presets` にある組み合わせ済みの3件はこの画面やマイジョブの通常入力で選ぶプリセットではない。マイジョブは独立マスターを組み合わせ、数量単位は主に `page` / `file`。簡易作業記録の大区分・詳細種類は独自の粗い選択肢で、初校校正や修正校正の重軽など既存マスターにない粒度も含む。両者の統合・係数流用は未決定。
- `WorkloadAnalyzerController` の月次ページ系集計には、全割当で自己割当を含めた後に自己割当を再加算する経路がある。新しい評価基準を設ける前に修正・検証する。既存順位と新しい確認済み実績時間を同じ尺度として見せない。
- 設定 (stages/sizes/types/difficulties) に coefficient を持たせ、割当／自己割当の estimated_hours 等と掛け合わせて合算する。
- 設定ページは XHR による保存（JSON 応答）を基本にし、保存成功時はトーストで通知する。
- ルーティングでは静的な `settings` をパラメタライズされたルートより先に定義すること（route cache に注意）。
