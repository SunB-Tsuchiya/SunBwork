# MGinbon 一覧再設計計画 2

作成日: 2026-09-19  
状態: 利用者承認済み・実装待ち

## 1. 目的

現行の1媒体1カード型一覧を廃止し、FileMakerのLIST／入稿チェックと同様に、
学校を一つの視覚単位として、その中へ媒体と国語・算数・社会・理科を固定配置する。
150校・約535媒体を扱っても、学校と四教科の関係を見失わず、横方向に工程を追える画面とする。

FileMaker由来の工程名・項目・意味は変更しない。表示を変えても正本データは共通とする。

## 2. 画面構造

### 2.1 表示切替タブ

初期実装は利用頻度の高い次の表示から始める。

1. `LIST`（初期表示）: 初校から校了までを横方向に追う総合進行表
2. `入稿チェック`: 入稿、文字入力、作図・スキャン点数、担当、発注・納品を中心に表示
3. `作業登録`: 一般ユーザーが作図・チェック・オペレーション・校正を自己登録する簡略表示

タブは同じ学校ブロックと検索条件を使い、表示列だけを切り替える。
将来、組版進行、発注表、スキャン発注、印刷・PDF用表示を同じ方式で追加できる構造にする。

### 2.2 媒体切替

表示タブとは別に、媒体フィルターを横並びで用意する。

- すべて
- 問題
- 解答のみ
- 解説解答
- 解答用紙
- 傾向と対策
- 冊子共通

存在しない媒体は学校ブロックへ空行を作らない。α版対象校だけに存在する媒体も同じ規則で表示する。

## 3. 一覧の単位

現行の媒体レコード単位ページングを、制作単位（通常は学校）単位へ変更する。

```text
学校ヘッダー: みくにコード / 日能研コード / 分類 / 学校名
  ├─ 問題
  │    ├─ 国語  [工程セル ...]
  │    ├─ 算数  [工程セル ...]
  │    ├─ 社会  [工程セル ...]
  │    └─ 理科  [工程セル ...]
  ├─ 解答のみ
  │    └─ 国語・算数・社会・理科
  ├─ 解説解答（存在する場合）
  ├─ 解答用紙（α版対象のみ）
  └─ 傾向と対策（対象校のみ）
```

- 学校名とコードは一度だけ大きく表示する。
- 媒体名を小見出しとして、その下に四教科を必ず国語・算数・社会・理科の順で並べる。
- 問題・解答のみは四教科一括の関係が分かる罫線と背景を使う。
- 科目単位で動くα版媒体も同じ学校ブロック内に置く。
- 1ページ10校を初期値とし、25校・50校へ切替可能にする。

## 4. LIST表示

- 左側の学校、媒体、科目をsticky表示する。
- 工程列はFileMakerと同じく左から右、上から下へ進行する順番にする。
- 工程グループは `入稿`、`初校`、`再校`、`三校以降` に分ける。
- 各セルは担当者、状態、日付を2段以内で表示する。
- `登録済`、`作業中`、`完了`、旧移行値を色と短いラベルで区別する。
- 学校ブロック全体から詳細編集へ移動でき、セルから該当MyJob詳細を開ける。
- 横スクロールは表の中だけに限定し、画面全体を横へ崩さない。

## 5. 入稿チェック表示

- 学校ヘッダーと四教科配置はLISTと共通化する。
- 表示列は入稿日、文字入力、作図、scan、社内・外注点数、発注日、納品日、初校担当を中心とする。
- FileMakerの色分けを基礎にしつつ、SBWorkのボタン・フォーム規則に合わせる。
- 四教科一括入力と個別入力を両方維持する。

## 6. 作業登録表示

- Coordinator用LISTと同じ学校・媒体・四教科配置を使う。
- 一般ユーザーが触れる工程だけを表示する。
- 空き、他者担当、自分の登録済み、作業中、完了をセル内で区別する。
- 自分の登録済みセルはMyJob詳細へ移動できる。
- 問題・解答のみは四教科選択を初期値、α版媒体は個別科目を初期値とする。

## 7. データ取得変更

- `mginbon_production_units`を検索・ページングの親とする。
- ページ内の制作単位に属する`items`、`item_subjects`、`stage_tasks`、`milestones`、
  `work_packages`をまとめて取得する。
- 同じ学校の媒体がページ境界で分断されないようにする。
- 件数表示は「媒体535件」だけでなく「学校／制作単位184件、媒体535件」を併記する。
- URLへ年度、表示タブ、媒体、検索、ページ数を保持する。

## 8. 実装段階

### Phase A: 共通データ構造

- Coordinator一覧APIを学校単位ページングへ変更
- 学校→媒体→四教科→工程の表示用データを構築
- 現在の検索・年度・媒体・確認状態を維持

### Phase B: Coordinator LIST

- 共通の学校ブロック／工程セルコンポーネントを作成
- LISTタブを初期表示として実装
- 担当者、状態、登録日、完了日、工程日付を表示

### Phase C: 入稿チェック

- 同じ学校ブロックへ入稿用列セットを適用
- 点数・担当・発注／納品日を編集可能にする

### Phase D: 一般ユーザー作業登録

- 同じ学校ブロックを簡略化して自己登録画面へ適用
- 既存MyJob登録API、4教科一括、個別選択を維持

### Phase E: 印刷・PDF

- 表示中の学校または選択した学校を印刷対象にする
- LIST／入稿チェックごとの印刷CSSとPDF出力を追加する

## 10. 検証条件

- 青山学院中等部で問題・解答のみ・α版媒体が同じ学校ブロックへまとまる。
- どの表示でも科目順が国語・算数・社会・理科になる。
- 学校の途中でページが分断されない。
- LISTと入稿チェックを切り替えても検索・年度・媒体条件が保持される。
- 自己登録、予定セット、完了が同じAssignment IDを使う。
- 完了後はMyJob、カレンダー、Coordinator LIST、詳細編集のすべてが完了表示になる。
- 旧FileMakerの工程名と日付項目を変更しない。
