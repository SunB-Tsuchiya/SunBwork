# SunBrain進行管理タブ整理 設計

更新: 2026-11-14。利用者は進行管理の「管理」「一覧」が混在するメニューを、案件関連と設定・管理に整理するよう依頼。サンエーは後日別途整理する既決定を維持する。同日の日報入口についての訂正は、既存の「日報管理」が日報チーム管理者用の閲覧・既読管理機能と確認した後、利用者が「その機能であれば追加」と再指定。最後の判断を採用する。

## 対象と配置案

- `companyType === 'sunbrain'` の進行管理だけ、新しい二段タブを使う。その他の会社と会社未選択時は従来タブをそのまま使う。
- 上段は「ダッシュボード / 日報閲覧（従来の日報管理が見える人だけ） / 案件・進行 / 取引先・担当者 / 管理・設定」。日報閲覧は既存 `diary_manager.diaryinteractions.index` の入口の表示名と位置だけを変える。権限・画面・URLは増やさない。
- 案件・進行: 案件一覧、ジョブ一覧、大まかな案件（現行の許可者のみ）、案件カレンダー、進行表一覧、管理シート一覧、銀本進行。銀本進行の別タブ動作を維持する。
- 取引先・担当者: クライアント管理、外注先管理、営業担当管理。
- 管理・設定: 設定、テストユーザー。従来の条件付き「日報管理」は、同じ `auth.isDiaryManager` 条件で上段の「日報閲覧」に移す。通常の進行管理者には表示されない。
- オペレーターカレンダーはSunBrainのメニューから外す。既存URL・画面・予約データ・通知処理は削除せず、保存済みURLからは開ける。
- 進行レポートはSunBrainメニューから外し、既存URL・画面は保持する案。10月8件、11月6件のGET（同月の進行管理 `project_jobs` 配下は805/508件、ジョブBOXは16/11件）。アクセス件数は利用者数・有効閲覧数ではない。利用者確認後に確定する。
- 既存ルート、権限、DB、`lastTab_coordinator` の保存値を変更しない。404時に保存先を消してダッシュボードへ戻る既存処理を維持する。一般ユーザーの試用公開は別判断。

## 調査・実装・検証

- 現行16入口、表示条件、銀本進行の別タブ、デスクトップ/モバイルを棚卸しする。16番目の「日報管理」は `diary_team_leaders` に登録された人だけに出る横断機能で、その既存権限を維持する。10～11月のアクセスログは利用者が許可した読み取り専用SSHで月別集計し、個別ログ行・IP・氏名は出力していない。
- 変更対象: `resources/js/Components/Tabs/CoordinatorNavigationTabs.vue` を会社別ラッパーにする。元の内容を `CoordinatorGeneralNavigationTabs.vue` に保存し、SunBrain用 `CoordinatorSunbrainNavigationTabs.vue` を追加。必要な設計・管理・再開資料と横断台帳、完了後のUI統合資料・変更履歴を更新する。
- 検証: 一般会社用と元部品の同一性、全残存入口のルート・表示条件、両画面幅でのメニュー定義、銀本の別タブ、対象ESLint、`/members`用Viteビルドとmanifest参照を確認。ビルドは画面確認を意味しない。
- 本番反映は利用者が許可した固定差分だけ。別作業の作業ツリー/本番未追跡ファイルを保持し、版が変われば書込み前に停止する。新しいメニューだけを利用者画面で確認する。
