## 目的と確定した利用者決定

同じ部署の仕事の埋まり具合を確認し、本人が記録すると自分の仕事が管理側に伝わることを実感できる画面を作る。評価点システム/管理画面は維持する。記録時間を勤勉さ・成果・評価の確定値としない。
2026-10-30会話で利用者は2タブ案にOKとし、設計/管理/再開用の3ファイルを作成して進めるよう依頼。一般公開やデプロイの許可とは扱わない。

- Userメニュー「部署の作業」の中に「部署の作業予定」「みんなの作業記録」。既定は予定。
- 通常の「予定表」は共有カレンダーを直接表示する現在の動作を維持する。
- 予定タブは既存部署ボードを使い、今日/今後の予定を確認できる。
- 記録タブは同部署全員の時間内訳バー。日単位、直近5営業日。名前/総時間/ジョブ/会議等で並替。点数と順位番号は表示しない。
- 仕事内容の色は既存カレンダーに合わせる。残業の独立強調/並替、週月集計、案件順位、係数、新旧点比較、詳しい分析は一般向けに設けない。
- 記録タブ上部は本人だけの案内。記録時間、仕事内容の未分類、勤務時間内の予定の空きを、根拠のある場合に表示。該当日の本人入力画面へのリンク。
- 予定タブの本人行付近にも「今日の記録を確認」を置く。他人の不足案内は表示しない。
- 会議/配分/応援も記録すると管理側へ反映されると説明。通常予定だから一律不十分としない。入力件数や分類選択だけのボーナスを追加しない。
- 最初は情報出版SuperAdminだけのプレビュー。一般公開は別途明示承認。

## 表示・データの境界

| データ | 取扱い |
| --- | --- |
| 氏名/同部署の記録時間 | 所属会社と部署をサーバ側で限定して返す |
| 内訳 | ジョブ（マイ/依頼は表示で合算可）・簡易作業・会議/外出・その他業務。既存色を共用 |
| private内容 | 件名/本文/案件名/ファイル/詳細リンクを公開しない。時間の扱いは既存認定条件と一致させ、私用は除外 |
| 点数/順位/係数/旧新比較/管理用内訳 | API応答にも含めない。既存管理分析APIをそのままブラウザへ返さない |
| 本人向け案内 | 認証本人についてだけ計算。user_idを指定して他人の案内を取得できない |
| 日付/会社/部署指定 | 日付の上限下限をサーバ検証。会社/部署は認証コンテキストから決定し任意指定で範囲拡大しない |

新しい表示用APIは専用コントローラ/サービスで認定時間データを取得し、許可した項目だけを明示構築する。既存管理API・既存試用入力APIのguardを緩めない。プレビューguardは既存PersonalWorkSchedule.availableを再利用する。将来の一般公開gateは読取専用に独立させる。

## 計算と説明

- V3の認定元、終了時刻、招待条件、休憩、UTC/JST、重複排除を再利用し、独自の時間合算を作らない。認定内訳合計と総時間が一致する。色分け時に残業を二重加算しない。
- 未分類: 種類の不足を指す。会議/その他業務など意味のある既存種別を、単にジョブでない理由で未分類としない。現行データから定義できる対象を実装前調査で確定する。分類不能は値を捏造せず案内なし/判定不可。
- 空き: 本人の有効な勤務時間帯から休憩と予定の時間の和集合を引く。勤務時刻が不明なら表示しない。現在日は未来の勤務時間を空きに含めず、現在時刻までの確定範囲を使う。未来予定だけで記録実績が増えない。予定カバーと認定済記録は区別して説明する。
- 勤怠と日報の義務は全員同じではない。日報なしを一律未記録/欠勤とみなさない。空きは「予定が入っていない時間」であり、未就労とは断定しない。
- 5営業日: 既存の共通営業日カレンダーの有無を調査する。休暇/所定勤務日を推定しない。共通休日情報がなければ初版は月〜金の5日を基準にして表示に明記し、祝日を除いた営業日とは称さない。休日当日の見せ方も実装前に記録する。期間の根拠が確定するまで一般公開しない。

## 画面と導線

既存Schedule/Index.vueに部署表示時だけ2タブを組込み、共有予定表示はそのまま。URLのtab=workを予定入口として維持し、記録タブは専用queryで識別、日付もURLに保持する。localStorageで戻り先を固定しない。読込中/失敗/データなしを明示し、古い日付のデータを新しい日付のものとして見せない。並替は同点時氏名順で安定化し順位番号を付けない。
本人の確認リンクは既存calendar.index等の本人入力導線へroute()で移動し、第三者のprivate詳細へ飛ばさない。一般向け個人詳細は初版で新設しない。既存予定ボードのprivate伏字を維持する。
