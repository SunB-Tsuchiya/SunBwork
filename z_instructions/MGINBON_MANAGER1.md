## 安全上の固定ルール

- FileMaker資料は社内機密として扱い、外部へ送信しない。
- 元DDR・CSV・Mergeを編集しない。
- 実データ、社員名、外注先名をログや公開ドキュメントへ列挙しない。
- 本番売上データを参照しない。
- destructive DB操作をサブエージェントへ委任しない。
- `migrate:fresh`等は対象DB名確認と`--database=`なしで実行しない。
- Sakura SSHはコマンド提示とユーザー承認後に行う。

## 現時点の技術判断

| 項目 | 判断 |
| --- | --- |
| モジュール | MGinbon専用モジュール |
| UI | FileMaker型管理台帳とCoordinator型作業用進行表の二層表示 |
| 正規データ | 専用MySQL接続`mginbon`内のMGinbon正規化テーブル |
| 年度分離 | 専用DB内の年度プロジェクトで分離。年度ごとの物理DBは作らない |
| WorkflowSheet | UI・連携パターンを再利用。正規データにはしない |
| ジョブ | `project_job_assignments`を共通キーとして利用 |
| 時間 | `events`を原則正規データとして集計 |
| 日報 | 構造化実績から候補生成。初期案はユーザー確定式 |
| 文字コード | CP932/Shift-JIS、CRLF、BOM対応 |
| 日付 | JSTの日付。date castは`date:Y-m-d` |
| 履歴 | 現在値とは別に変更履歴を保持 |
