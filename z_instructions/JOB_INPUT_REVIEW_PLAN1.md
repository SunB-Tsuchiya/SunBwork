## 概要

**2026-10-13 の追加・旧方針の訂正:** 既存の「大まかな案件」区分はない。先の「既存本筋を探す」案は撤回。情報出版 Super Admin で独立した大まかな案件を先に登録し、簡易予定から選ぶ。名前必須、取引先・年度任意。既存 ProjectJob との紐づけ、ProjectJob 登録時選択、Coordinator メニューは皆で使う段階の後工程とする。詳細と進捗は `BROAD_PROJECT_PLAN1.md` / `BROAD_PROJECT_MANAGER1.md` に記録。以下の旧記述と食い違う場合はこの決定を優先する。

カレンダーの「簡単な作業予定」を、少ない操作でその日の活動を残せる試用入力として整える。カレンダーの時刻表で選んだ開始・終了と作業の手掛かりを最初に置き、ページ数・数量は任意のまま常時表示する。進みなどは必要な人だけ開く。独立した「作業時間」入力欄や分数だけの入力は設けない。予定はその日の活動記録として扱い、毎件の実施確認は求めない。日報本文は本人の自由記述を維持し、タイムテーブルには簡易予定も表示する。日報作成時には大きな時間の抜けを非強制で知らせる。

入力が定着してから、使い慣れたマイジョブ登録画面にこの短い入力を取り込む。依頼ジョブをマイジョブへ取り込む流れ、依頼元・ファイル・進行表との関係は保持する。依頼ジョブの入力項目は、その後に同じ考え方で整理する。独立した `work_record_trials` は機能を増やさない。

### 結論として扱える範囲

- 難易度は入力欄を日常フォームから外してよい。既存の値・旧分析の参照は移行判断まで保持する。
- サイズは仕事の寸法・案件の属性として残せるが、作業者の査定用の必須入力にはしない。案件からの引き継ぎや進行表の固定値は消さない。
- 数量は使う人がいる。試用画面ではページ数・数量を任意の常時表示項目とし、点数の直接倍率にはしない。単位はページを初期値にし、件・枚などに変更できる。
- 工程・作業種別は人によって利用差がある。共通の必須欄にせず、職種・過去入力から初期値を提案するか、必要な人だけ詳細で選べるようにする。
- 締め切り日は現行画面で当日が初期値になるため、入力率から必要性を判断しない。依頼時には任意の納期として残し、本人の当日作業時間と区別する。

## 3つの入口の項目整理案

| 入力 | 最初に見せる | 必要時だけ見せる・引き継ぐ | 日常入力から外す |
| --- | --- | --- | --- |
| カレンダー簡易入力（先に改修） | 日付、カレンダーで選んだ開始・終了、作業区分の初期値、案件を探す、短い作業名、任意のページ数・数量と単位 | 仮案件名、進み・結果、作業種類、部署表示範囲 | 独立した作業時間欄、難易度、サイズ、見積時間、依頼用の締め切り |
| マイジョブ（簡易入力の検証後） | 案件または仮の手掛かり、ジョブ名、日付と時間、届いた依頼 | 依頼元、過去データ流用、概要、数量、工程・種別、ファイル | 難易度・サイズの通常入力、見積時間の通常入力 |
| 依頼ジョブ（マイジョブ整理後） | 案件、依頼先、ジョブ名、必要なら納期 | 詳しい指示、ファイル、工程・種別、進行表リンク | 難易度・サイズを全件に入力させる欄、見積時間の通常入力 |

作業名・案件名を空欄にしても、非案件作業は区分の名称で表示できるようにする。曖昧な記録は日報作成時に見直しを勧める案内にとどめ、登録自体を止めない。取引先・年度の異なる同名案件は検索結果で区別し、完了案件は初期状態で隠す。既存の完了案件を編集するときは選択済みのものを表示する。

## 修正順序

1. **既存の簡易入力だけを試用改修**: `QuickWorkEntryModal.vue` と案件候補 API を使い、常設30件リストを「案件を探す」モーダルへ移す。カレンダーで選んだ開始・終了を必須にし、画面で訂正できるようにする。従来の午前・午後・終日の大まかな予定枠は新規登録では選ばせず、保存時には内部的に時間指定として扱う。試用時のフィードバックを受け、ページ数・数量は任意で常時表示し、進み・表示範囲は必要時に開ける配置にする。分数入力欄は作らない。
2. **活動記録の読み方を統一**: `WorkloadTrialAnalysis` と日報の注意表示から、結果文の必須条件を外す。未来の予定、休憩、重複、非公開の扱いを既存規則に沿って確認する。日報は自由記述を維持し、本人の簡易予定をタイムテーブルにだけ重ねる。試用中の「予定を反映する」入力欄は撤去し、以前の日報作業結果は保持する。
3. **Super Admin だけで実例確認**: 短い仕事を1日に多数切り替える日、長期案件、仮案件、依頼からの転換、時間だけの入力、修正・削除を比較する。全員公開と採点変更は別判断とする。
4. **マイジョブ・依頼ジョブへ反映**: 既存 `AssignmentForm.vue` の利用経路と必須値を壊さず、本人用の初期表示を短くする。依頼側は担当者・納期・ファイル・進行表リンクを保持して整理する。旧レコードのサイズ・難易度は削除しない。

### 2026-10-13 追加工程: 人別の詳細表示（横断台帳 P11）

利用者は「作業実績の内訳」の人名を押すと、その人の詳細を見たい。日表示では時刻順の予定と内容、週・月表示では日別の集計を示す。現在のカードは件数・時間の合計だけで、元の予定の日時と照合できない。

- 対象ファイル: `WorkAnalysis.vue`、`DepartmentWorkController.php`、`WorkloadTrialAnalysis.php`。既存の試用分析 API に許可済み対象者の個別取得を加え、日別の認定時間・件数・暫定作業点を同じ集計処理から返す。日表示の予定は既存の部署作業 API の公開範囲を踏襲して時刻順に表示する。

2026-10-13、利用者が同じ15分の簡易予定を2件置いたところ、カレンダー日表示では一方のバーが上に載り、2件あることが分からなかった。日報などのタイムテーブルは並列表示される。主工程後に日カレンダーの重複配置とクリック先を調査し、各件が見分けられ、個別に詳細を開けるようにする。マイジョブ、依頼ジョブ、一般予定の同種・異種の重なりも確認する。これら他種類の不具合はまだ確認されていない。重複時間の試用集計除外は画面確認済みであり、表示の修正と分けて扱う。
