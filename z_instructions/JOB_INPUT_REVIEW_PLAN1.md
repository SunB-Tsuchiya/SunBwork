# ジョブ入力の総点検・簡易入力の改修計画

更新: 2026-10-12。まず概要、その後に根拠と実装順を示す。第1段階はローカル実装中。既存データ・本番画面・採点式は変更しない。

## 概要

カレンダーの「簡単な作業予定」を、少ない操作でその日の活動を残せる試用入力として整える。カレンダーの時刻表で選んだ開始・終了と作業の手掛かりを最初に置き、数量・進みなどは必要な人だけ開く。独立した「作業時間」入力欄や分数だけの入力は設けない。予定はその日の活動記録として扱い、毎件の実施確認は求めない。日報本文とタイムテーブル表示は現状維持し、日報作成時に大きな時間の抜けを非強制で知らせる。

入力が定着してから、使い慣れたマイジョブ登録画面にこの短い入力を取り込む。依頼ジョブをマイジョブへ取り込む流れ、依頼元・ファイル・進行表との関係は保持する。依頼ジョブの入力項目は、その後に同じ考え方で整理する。独立した `work_record_trials` は機能を増やさない。

### 結論として扱える範囲

- 難易度は入力欄を日常フォームから外してよい。既存の値・旧分析の参照は移行判断まで保持する。
- サイズは仕事の寸法・案件の属性として残せるが、作業者の査定用の必須入力にはしない。案件からの引き継ぎや進行表の固定値は消さない。
- 数量は使う人がいる。任意の「詳しい記録」に残し、点数の直接倍率にはしない。
- 工程・作業種別は人によって利用差がある。共通の必須欄にせず、職種・過去入力から初期値を提案するか、必要な人だけ詳細で選べるようにする。
- 締め切り日は現行画面で当日が初期値になるため、入力率から必要性を判断しない。依頼時には任意の納期として残し、本人の当日作業時間と区別する。

## 3つの入口の項目整理案

| 入力 | 最初に見せる | 必要時だけ見せる・引き継ぐ | 日常入力から外す |
| --- | --- | --- | --- |
| カレンダー簡易入力（先に改修） | 日付、カレンダーで選んだ開始・終了、作業区分の初期値、案件を探す、短い作業名 | 仮案件名、数量と単位、進み・結果、作業種類、部署表示範囲 | 独立した作業時間欄、難易度、サイズ、見積時間、依頼用の締め切り |
| マイジョブ（簡易入力の検証後） | 案件または仮の手掛かり、ジョブ名、日付と時間、届いた依頼 | 依頼元、過去データ流用、概要、数量、工程・種別、ファイル | 難易度・サイズの通常入力、見積時間の通常入力 |
| 依頼ジョブ（マイジョブ整理後） | 案件、依頼先、ジョブ名、必要なら納期 | 詳しい指示、ファイル、工程・種別、進行表リンク | 難易度・サイズを全件に入力させる欄、見積時間の通常入力 |

作業名・案件名を空欄にしても、非案件作業は区分の名称で表示できるようにする。曖昧な記録は日報作成時に見直しを勧める案内にとどめ、登録自体を止めない。取引先・年度の異なる同名案件は検索結果で区別し、完了案件は初期状態で隠す。既存の完了案件を編集するときは選択済みのものを表示する。

## 修正順序

1. **既存の簡易入力だけを試用改修**: `QuickWorkEntryModal.vue` と案件候補 API を使い、常設30件リストを「案件を探す」モーダルへ移す。カレンダーで選んだ開始・終了を必須にし、画面で訂正できるようにする。従来の午前・午後・終日の大まかな予定枠は新規登録では選ばせず、保存時には内部的に時間指定として扱う。数量・進み・表示範囲を必要時に開ける配置にする。分数入力欄は作らない。
2. **活動記録の読み方を統一**: `WorkloadTrialAnalysis` と日報の注意表示から、結果文の必須条件を外す。未来の予定、休憩、重複、非公開の扱いを既存規則に沿って確認する。日報は自由記述とタイムテーブルを維持する。
3. **Super Admin だけで実例確認**: 短い仕事を1日に多数切り替える日、長期案件、仮案件、依頼からの転換、時間だけの入力、修正・削除を比較する。全員公開と採点変更は別判断とする。
4. **マイジョブ・依頼ジョブへ反映**: 既存 `AssignmentForm.vue` の利用経路と必須値を壊さず、本人用の初期表示を短くする。依頼側は担当者・納期・ファイル・進行表リンクを保持して整理する。旧レコードのサイズ・難易度は削除しない。

第1・2段階で想定する主なファイル: `resources/js/Components/Calendar/QuickWorkEntryModal.vue`、`app/Http/Controllers/Schedule/DepartmentWorkController.php`、`app/Services/WorkloadTrialAnalysis.php`、`app/Http/Controllers/DiaryController.php`、`resources/js/Components/Diaries/DiaryWorkReminder.vue`。日付だけから開いた場合は開始・終了を空欄で表示し、カレンダーの時刻表に沿って入力してから保存する。独立した作業時間入力は設けず、内部集計用の分数は開始・終了から算出する。DBの破壊的変更や本番反映はこの段階に含めない。

## 検証

- カレンダーで選んだ開始・終了の引き継ぎと後からの変更、タイムテーブル表示、未来の予定の除外、日報の非強制の注意を、少数の架空データで確認する。
- 依頼からマイジョブへの転換、既存レコードの編集・読み取り、完了案件の再編集を確認する。
- Vue変更後はビルドし、対象のPHPファイルは構文確認する。DB初期化を伴う共通テストは使わない。
