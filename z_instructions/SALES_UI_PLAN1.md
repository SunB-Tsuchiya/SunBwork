# SALES_UI_PLAN1.md — 売上分析レイアウト再設計（全幅化後のコンパクト化・構成比可視化導入）

最終更新: 2026-10-09

## 1. 背景

2026-10-09に売上分析配下14画面のヘッダーを`AppLayout`から`SalesAnalysisShell.vue`へ全面移行し、
画面幅いっぱいを使えるようにした（詳細は`SALES_ANALYSIS_MANAGER1.md`の該当日の作業ログを参照）。
結果、ユーザーから「表が横に伸びて見にくくなった」とのフィードバックを受けた。単に幅を解放しただけで、
各画面の中身（カード・表・グラフ）が従来のまま単カラム縦積み構成だったため、要素が間延びして見える
画面と、逆に列数の多い表が窮屈なままの画面の両方が存在する状態になっている。

本書は、調査結果を踏まえた再設計方針・対象画面・実装順序を記録する。

### 構成比の可視化が意味を持ちそうな箇所

- 得意先別の受注金額構成比（ClientAnalysis / MonthlyAnalysis / AnnualAnalysis等の得意先ランキング）
- 受注経路（サンエー印刷経由/独自受注）比率（SUNBRAINのみ、各画面のKPI帯）
- 部署別経費の科目構成比（FiscalYearAnalysisの経費セクション、ExpenseComparison）
- 分類別/項目別の売上構成比（各画面の分類/項目タブ）

現状はいずれも表の`share_pct`列でしか構成比を確認できず、視覚化が無い。

## 3. 設計方針

### 3.1 2カラム化の基本ルール

- 「グラフ（推移・比較）カード」と「ランキング/明細テーブルカード」が縦に並んでいる箇所は、
  `grid gap-4 lg:grid-cols-2 lg:items-start`で横並びにする（ExpenseComparison.vueで採用済みの
  パターンをそのまま横展開する）。
- **時系列そのものを表す表・グラフ**（月別推移の折れ線、得意先×年のマトリクス等）は構造上
  横に長いことが自然なため、無理に2カラム化しない（間延びして見えるのではなく、時系列データを
  横に並べて見比べるのが本来の目的のため）。
- 列数が多い一覧表（ImportHistory 11列、経費の月別表 14列）はフル幅のままにする（フル幅化の
  恩恵が最も出ている箇所であり、無理に狭めるとかえって読みにくくなる）。
- KPIカード帯は現状のグリッド構成（`grid-cols-1 sm:grid-cols-2 lg:grid-cols-5`等）を維持する。

### 3.2 構成比可視化の導入（円グラフ→横棒積み上げへ設計変更）

`dataviz` skill（Artifact/チャート作成前に必ず参照するプロジェクト共通スキル）を適用した結果、
**円グラフではなく横棒の積み上げ1本（Top N＋その他）**を採用することにした。理由:
- `dataviz`skillの`choosing-a-form.md`は part-to-whole の既定フォームを「stacked bar
  （横に長い/ラベルが長いカテゴリはhorizontal）」としており、円グラフは推奨フォーム表に
  一度も登場しない。`components.md`にも明記: 「part-to-whole rides on the stacked bar
  chart; donut stays deprioritized」。
- 得意先名・科目名は長い日本語文字列になりやすく、角度比較が苦手な円グラフより、
  直接ラベル＋横棒のほうが正確に読み取れる。
- 色は`validate_palette.js`で隣接CVD分離（ΔE light 9.1 / dark 8.4、通常視力ΔE light 19.6 /
  dark 19.3、いずれも基準クリア）を確認済みの固定順パレット（blue/orange/aqua/yellow/
  magenta、6番目以降は「その他」として中立グレー1色に集約）を採用。既存UIのアクセント色
  （indigo等）とは独立した「作図専用パレット」として扱う（本文テキストやボタンの配色は
  従来どおりindigo系のまま変更しない）。

新規共通コンポーネント`resources/js/Components/SalesAnalysis/ShareCompositionBar.vue`を新設した
（実装済み）。

- props: `rows`（`{label, amount}`の配列。既存のRankingPanel用データをそのまま渡せる）、
  `topN`（既定5）、`title`（任意）、`formatValue`（金額フォーマッタ、既定で¥表記）。
  新規API呼び出しは不要（既存のランキングAPIレスポンスをそのまま渡す）。
- 積み上げ棒（セグメント間2pxの余白）＋直接ラベルの凡例（色見本・名称・金額・構成比%を
  常時表示、ホバー不要で全件の数値が読める）。`role="img"`＋各セグメントに`title`属性で
  簡易ツールチップも付与。
- 配置先（3.3節の各画面の節を参照）は「ランキング表の隣（2カラムの片側）」を基本とし、
  表と同じデータを別の見せ方で補完する位置づけにする（表を置き換えるのではなく併設する）。

### 3.3 画面別の改修内容

実装は4.1節の優先順位に従って段階的に行う（1画面を完成させてからユーザー確認→横展開、という
Phase12の進め方を踏襲する）。

#### 月次分析（MonthlyAnalysis.vue）— 完成見本として最初に着手

- 「同月複数年比較」グラフカードと「得意先比較」カード（横棒グラフ＋RankingPanel表）を
  `lg:grid-cols-2`で横並びに変更。
- 「分類別」「項目別」タブパネルに`ShareCompositionBar`を追加し、RankingPanel表と並べて
  構成比を可視化する（`lg:grid-cols-2`、左に表、右に構成比の積み上げ棒）。
- KPI5枚帯は変更しない。

#### 年次分析（AnnualAnalysis.vue）・期別分析（FiscalYearAnalysis.vue）

- 月別推移の折れ線グラフカードは単カラムのまま維持（時系列のため）。
- 得意先別RankingPanelと分類/項目タブを、月次分析と同じ「表＋`ShareCompositionBar`」の
  2カラムパターンへ変更。
- 期別分析の経費セクション: 部署内の科目別構成比を示す`ShareCompositionBar`を、月別科目表の
  上部または隣に追加する（折半バッジ等の既存UIは変更しない）。

#### 得意先分析（ClientAnalysis.vue）・商品分析（ProductAnalysis.vue）

- 個別詳細（対象 vs 部署合計の棒グラフ＋年別表）とランキングパネルを`lg:grid-cols-2`で横並びに変更。
- ランキングパネル側に`ShareCompositionBar`（得意先別/商品別の構成比）を併設する。

#### 同月比較（SameMonthComparison.vue）・左右比較（SideBySideComparison.vue）

- 既に2カラム化済みの部分は変更しない。得意先別年次推移マトリクス・年別テーブルは
  構造上横長が自然なため変更しない。
- `ShareCompositionBar`は、左右比較のA/B期間それぞれの分類別構成比に追加できないか検討する
  （優先度は低、他画面完了後に判断）。

#### 変更しない画面

RegistrationStatus（軽微）、ClientGroups（設定画面で表は細め）、ImportHistory（フル幅の恩恵あり）、
Import/ExpenseImport/ImportHub（フォーム中心）。

## 4. 実装順序・受入基準

### 4.1 実装順序

1. `ShareCompositionBar.vue`新設（単体で動作確認できる最小構成）
2. 月次分析（MonthlyAnalysis.vue）を完成見本として改修 → ユーザー確認
3. 年次分析・期別分析へ横展開
4. 得意先分析・商品分析へ横展開
5. 同月比較・左右比較への構成比可視化追加（優先度低、必要に応じて）
6. npm run build・SalesAnalysis全テスト

### 4.2 受入基準

- 新規に追加するグラフ・2カラム化は既存のAPIレスポンス（`share_pct`等）をそのまま使い、
  新規バックエンドAPI呼び出しは発生させない（フロントエンドのみの変更）。
- 時系列表現（月別推移・年別マトリクス）・列数の多い一覧表（取込履歴・経費月別表）は
  無理に2カラム化しない。
- モバイル幅（`sm`未満）では従来どおり単カラム縦積みに戻る（`lg:grid-cols-2`はlg以上のみ適用）。
- 既存のSalesAnalysis配下PHPUnitテストに影響を与えない（フロントエンドのみの変更のため）。
