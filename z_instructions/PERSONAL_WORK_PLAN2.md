# PERSONAL_WORK_PLAN2 — 実績比較の試用

作成日: 2026-10-09。対象は情報出版部署のローカル試用。本番デプロイ対象外。

## 目的と判定

- 朝の予定だけでは「認定実績」0件。未記録は作業量ゼロとは表示しない。
- 結果文・作業種類・実績時間が揃う行のみ認定実績に加える。予定行を細かく分割しただけで点が増える仕組みは作らない。
- 作業種類を選び、同じ作業種類の人別記録時間・件数・単位別数量を日・週・月で比べる。数量順位は同じ単位に限る。時間は投入時間であり生産性点ではない。
- 比較欄は記録量の可視化であり、人事査定の自動点数としない。現行の作業量分析スコアへ加算しない。
- 2026-10-09 追加決定: 上長と表示可否を相談するための暫定ポイントを試作する。`actual_minutes / 60 × 10 × 作業種類係数` を小数1桁で合算する。結果文・作業種類・実績時間が不足する行は0点。数量は点数に入れない。係数はコード内の小さな表で公開し、制度化前に調整する。
- 既存の部署内権限・非公開案件のフィルタを分析 API で維持する。

## 画面

- 上部に期間内の記録者数・認定実績件数・記録時間を表示。
- 作業種類選択で人別比較を表示。時間順を初期表示し、同じ単位で入力されている場合だけ数量でも並べ替えられる。
- 下部に人別の作業区分の積み上げ棒と、各作業種類の時間・件数・単位別数量を表示する。
- 暫定ポイント順位を期間全体で表示し、作業種類別の係数と獲得ポイントを人別の内訳でも示す。
- ポイント順位を左、同じ作業種類の比較を右へ並べる。担当色はユーザー登録の `assignment_id`（進行管理・オペレーター・校正・制作・営業）を優先し、登録担当が該当しない Clerk を事務色にする。個別の作業区分は下部の内訳棒で別色として表示する。
- 日表示は既存の結果未入力予定を別表示する。未入力予定は比較に加えない。

## 試用データ

- ローカル専用、専用メールドメイン `.invalid` の架空利用者を複数職種に配置。組版・校正・進行管理は同じ作業種類を複数人が記録する。
- 2026年9月と10月上旬に、入力密度と結果記入率に差をつけた簡易予定・自己割当ジョブ・イベント・結果記録を作る。
- 固定プレフィックスとメールで識別可能にし、本番環境では Seeder が例外で停止する。既存利用者・案件は更新しない。再実行時の重複防止を設ける。

## 変更箇所と検証

- `app/Http/Controllers/Schedule/DepartmentWorkController.php`: 比較向け集計の付加。既存の権限フィルタ後の実績だけで計算。
- `resources/js/Pages/Schedule/WorkAnalysis.vue`: 比較欄、人別棒、未記録の案内。
- `database/seeders/PersonalWorkDemoSeeder.php`: ローカル専用の試用データ。
- `tests/Feature` または `tests/Unit`: 認定・数量単位・部署権限の重要な検証。
- Vue ビルド、対象テスト、ローカル試用データの表示値確認。
