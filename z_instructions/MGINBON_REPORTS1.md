# MGinbon 印刷・PDF帳票設計 1

作成日: 2026-09-18  
状態: 代表帳票画像確認済み

## 1. 方針

MGinbonの進行データから印刷専用HTMLを生成し、ブラウザーの印刷機能で紙へ印刷またはPDFへ保存する。
初期版ではサーバー上にPDFファイルを生成・保管せず、常に最新の正規データから帳票を表示する。

- 印刷プレビューを用意する
- `@media print`でナビゲーション、操作ボタン、内部UIを除外する
- A4縦／横、改ページ、繰り返しヘッダーを帳票ごとに定義する
- 印刷時刻、年度、抽出条件をヘッダーまたはフッターへ表示する
- 社員名・外注先名等は社内帳票だけに表示可能とし、クライアント共有帳票には出さない
- Mac用・Windows用を別帳票にせず、Webの共通印刷レイアウトへ統合する
- 紙原稿と一緒に回覧し、作業時間や確認結果を手書きする運用を維持する
- FileMaker帳票に近い、年度・媒体見出し、学校情報、工程の縦並び、担当者欄、日付欄、
  手書き用の余白と枠を維持する

## 2. DDRで確認できた帳票系レイアウト

### 出稿表

- 出稿表_問題
- 出稿表_解答のみ
- 出稿表_解説解答
- 出稿表_傾向と対策
- 出稿表 α版解説 for mac
- 出稿表_問題 for mac
- 出稿表_解説解答 for mac

Web版では媒体・商品・年度・学校・科目の条件で一つの出稿表機能から生成し、Mac専用版を作らない。

代表画像から、出稿表は一覧帳票ではなく紙原稿に添付して回す学校／科目別の作業票であることを確認した。

- 問題・解答のみ: 学校単位で1枚。4科目をまとめて動かす
- 解説解答等: 科目単位で1枚。科目欄の対象教科へ赤丸を付ける
- 帳票上部: 年度、媒体、みくにコード、日能研コード、分類、学校分類、学校名、科目、銀本掲載
- 入稿部: 入稿日、文字UP、手書きメモ欄
- 工程部: 作図、初校、初校チェック、初校出、初校校正、再校、再校出、再校校正、三校以降、校了
- 工程行: 段階、役割、担当者、手書き作業時間欄
- 補助文言: `突き合わせ→`、`赤字照合→画像確認→`等
- 下部: 校了日等の手書き・押印相当欄

### 発注書

- C&C 文字入力発注書
- 大連 作図発注書
- 原本スキャン発注書
- 原本スキャン発注書（解答用紙）

固有の外注先名を帳票種別名へ固定せず、「文字入力発注書」「作図発注書」「原本スキャン発注書」とし、
宛先には既存`subcontractors`から選んだ外注先を表示する。過去データ取込では元の宛先を保持する。

文字入力発注書の代表画像から、FileMaker側は次の二つの表示を使い分けていることを確認した。

- レコード画面: 複数校を縦に並べ、学校ごとに4教科の発注日・納品日を確認・入力する管理用一覧
- 印刷物: 一覧で選択した複数レコードをA4縦へ順番に羅列し、紙原稿とともに使用する発注書

発注書の上部には宛先、年度、案件名、帳票名を置き、その下にみくにコード、日能研コード、
日能研分類、学校名、媒体分類と、4教科別の発注日・納品日を配置する。学校名が長い場合も1行内で
可読性を保つ。下部の会社情報は帳票設定から取得し、個人名・電話番号・メールアドレスを
テンプレートへ固定値として埋め込まない。

印刷操作では一覧上でチェックしたレコードを対象とし、選択順または指定した並び順で連続出力する。
1ページへ収まる複数校（代表画像では約8校）を縦に詰め、次の学校から自動改ページする。全件選択時は
10ページを超えることもあるため、ページ数に上限を設けず、印刷前に選択件数と推定ページ数を表示する。
学校1件分のブロックはページ境界で二つに分断しない。入力値が空欄の日付欄は紙への手書きができる
空枠として残す。

作図発注書（画面上の名称は「文字＆作図 外注」）も、管理画面でレコードを選択し、選択分を印刷する。
ただし文字入力発注書とは異なり、印刷単位は1校1ページである。複数校を選択した場合は、学校ごとに
必ず改ページして連続出力する。

代表画像で確認した作図発注書の項目:

- 年度、案件名、みくにコード、日能研コード、日能研分類、学校名、媒体分類、科目、学校分類
- 4教科別の入稿日、文字入力先、文字入力の発注日・納品日
- 4教科別の作図先
- 外注スキャン数、外注作図数、社内スキャン数、社内作図数と各合計
- 作図等の発注日・納品日、初校組担当
- 銀本掲載、問題原本入稿日、備考
- 上部の作図総合計、スキャン総合計、金額欄

点数がない欄は、FileMakerデータ上の空欄と0を業務上同じものとして扱う既定ルールに従い、表示設定で
空欄または0を選べるようにする。上部の作図総合計・スキャン総合計は、現在の検索・絞り込み対象レコードを
母集団として外注先別に集計する。金額は各合計点数に対応する単価を掛けて算出する。印刷用チェック対象の
合計とは分けて表示する。実績値の正本は`mginbon_work_measurements`とし、帳票専用の重複値は持たない。

単価は少なくとも`年度×外注先×作業種別（作図／スキャン等）`で設定する。年度途中の改定に備えて
適用開始日・適用終了日を持てる構造とし、実績確定時に適用した単価または単価版を記録する。
点数管理は単価未設定でも利用可能にし、金額欄は未設定であることが分かる表示にする。

金額計算の丸め、消費税、締め期間、発注後の単価変更時の再計算可否は、集計担当者のレビュー後に確定する。
初期設計では推測による会計ルールを組み込まない。

原本スキャン発注書（画面上の名称は「本画像スキャン 発注書」）は、文字入力発注書と同様に、選択した
複数校を1ページへ縦に並べ、収まらない分を自動改ページする。代表画像では1ページに約6校を配置する。
ヘッダーには年度、案件名、帳票名と、現在の検索・絞り込み結果（FileMakerの対象レコード）に含まれる
スキャン点数合計を表示する。この合計の母集団は印刷用にチェックしたレコードではなく表示対象集合である。

- 全レコード表示時: 問題、解答のみ、解説解答、解答用紙、傾向と対策等を含む全媒体の合計
- 学校で絞り込み時: その学校に属する媒体別レコードを横断した合計
- 媒体や分類で絞り込み時: その条件に一致するレコードだけの合計

Web版では誤解を防ぐため、`表示対象 N件 / スキャン合計 X点`と母集団を明記する。印刷対象のチェック件数と
点数もプレビュー前に別表示し、表示対象合計と印刷選択合計を混同しない。

印刷物へ出す学校別項目:

- みくにコード、日能研コード、日能研分類、学校名、媒体分類
- 国語・算数・社会・理科別のスキャン点数と学校別合計
- 4教科別の発注日・納品日

管理画面ではこれに加えて、問題初校担当、原本入稿日、原本スキャン担当、銀本掲載を表示するが、
外注先へ渡す印刷物には出さない。したがって、同じ正規データを参照しながら、管理画面列と帳票公開列を
別設定にする。学校ブロックはページ境界で分断しない。

「原本スキャン発注書（解答用紙）」は同じ画面・印刷構造で、媒体分類を`解答用紙`へ絞ったものと
確認した。別個の固定帳票を複製せず、共通の原本スキャン帳票テンプレートへ媒体条件を渡して生成する。
解答用紙は紙面全体をそのままスキャンするため、通常は各教科1点または2点程度となる。

解答用紙はα版だけに付く。年度別α版対象校リストで解答用紙媒体が有効な学校・入試回だけを管理画面の
候補および発注書の選択対象にする。通常校や、α版対象でも解答用紙媒体を持たない制作単位には、
解答用紙スキャン工程を自動生成しない。対象判定は学校マスターへ固定せず、年度別の
`mginbon_publication_items`相当の媒体有効情報を参照する。

スキャン数量は成果物の大きさや媒体を問わず、実際にスキャンした1成果物を`1点`として数える。
10mm角の図版もA3用紙1枚を丸ごとスキャンしたものも同じ1点であり、外注実績・費用集計では共通の
点数として合算できる。データには媒体分類を残すため、必要なら問題図版と解答用紙の内訳を再集計できる。

## 3. 初期リリースへ含める印刷

1. 管理台帳の現在の抽出結果
2. みくに出版向け共有進捗表
3. 出稿表（媒体・商品別）
4. 文字入力発注書
5. 作図発注書
6. 原本スキャン発注書（通常／解答用紙）

一覧の単純印刷と業務帳票を分ける。管理台帳の横長表をそのまま縮小して発注書にせず、発注書は
必要項目だけを組み直す。

## 4. 出稿作業票の印刷単位

| 媒体 | 既定の印刷単位 | 科目表示 |
| --- | --- | --- |
| 問題 | 学校／入試回単位で1枚 | 4科目をまとめて表示 |
| 解答のみ | 学校／入試回単位で1枚 | 4科目をまとめて表示 |
| 解説解答 | 学校／入試回×科目で1枚 | 対象科目へ赤丸 |
| 解答用紙 | 学校／入試回×科目を既定 | 対象科目へ赤丸。年度設定で変更可 |
| 傾向と対策 | 年度×学校×科目を既定 | 対象科目へ赤丸 |

帳票発行前に対象科目をチェックで変更できる。赤丸は印刷CSSで明確に表示し、白黒印刷でも識別できる
よう太枠または丸印を併用する。学校単位帳票を4科目分へ不要に複製しない。

## 5. 帳票テンプレートのカスタマイズ

FileMakerのレイアウト編集と同等の自由配置エディターを初期版で再現するのではなく、帳票の業務構造を
壊さない範囲で次を設定可能にする。

- 工程行の表示／非表示
- 工程行の順序
- 帳票上の表示名（例: 初校校正、再校校正）
- 役割ラベル（OP、初校チェック等）
- 工程間の補助文言（例: `突き合わせ→`、`赤字照合→画像確認→`）
- 手書き作業時間欄、メモ欄、校了欄の表示
- 媒体ごとの学校単位／科目単位の既定
- 帳票上部の任意短文

設定は年度テンプレートとして複製できる。自由入力したHTMLやスクリプトは許可せず、文字列は安全に
エスケープする。各帳票を出力した時点のテンプレート版を記録し、後の設定変更で過去出力の意味が
追えなくならないようにする。

候補テーブル:

- `mginbon_report_templates`: 年度、媒体、帳票種別、印刷単位、用紙、向き、設定JSON、版
- `mginbon_report_template_rows`: 工程定義、表示名、役割名、補助文言、順序、手書き欄設定
- `mginbon_report_exports`: 出力者、出力日時、対象条件、テンプレート版（PDF自体は保存しない）

## 6. 出力単位

### 管理台帳・共有進捗表

- 現在の年度・フィルター・表示ビューを引き継ぐ
- 印刷前に件数と対象条件を確認
- クライアント共有版は公開allowlistだけを使用

### 出稿表

- 年度
- 商品／媒体
- 学校または制作単位
- 科目（単科または4科目）
- 対象工程・出稿日
- 必要な識別コード

### 発注書

- 発注日、納期
- 宛先外注先
- 学校、媒体、科目
- 作業種別
- 点数・数量
- 備考

画面と印刷物の責務は分ける。

- 管理画面は複数レコードを一覧し、4教科の日付を一括入力・修正できる
- 印刷プレビューはチェックした複数レコードを連続表示する
- 「表示中をすべて選択」「すべて解除」と個別チェックを用意する
- 検索・絞り込み後の全選択は、現在の抽出結果だけを対象にする
- 1ページへ複数レコードを配置し、レコードブロック単位で改ページを制御する
- 発注書を印刷しても進捗値は変更しない
- 発行日時・発行者・対象レコード・テンプレート版だけを出力履歴へ記録する

帳票種別ごとのページング:

| 帳票 | 選択方式 | 印刷配置 |
| --- | --- | --- |
| 文字入力発注書 | 複数選択 | 1ページに複数校を羅列して自動改ページ |
| 作図発注書 | 複数選択 | 1校1ページで学校ごとに改ページ |
| 原本スキャン発注書（問題等） | 複数選択 | 1ページに複数校（代表画像では約6校）を羅列して自動改ページ |
| 原本スキャン発注書（解答用紙） | 複数選択 | 問題等と同じ共通帳票。数量単位は共通の「点」 |

金額・単価は初期版の必須項目にしない。

## 7. 権限

- 管理権限グループ: 全社内帳票のプレビュー・印刷
- Proof Admin: 校正関連の一覧印刷。発注書は初期対象外
- User: 自分の作業一覧の印刷のみ。発注書・全体台帳は不可
- 共有URL閲覧者: 公開進捗表の印刷のみ

## 8. 受領済み資料と次の資料

問題と解説解答の代表的な帳票画像を受領し、学校単位／科目単位、赤丸、手書き欄、工程補助文言、
縦方向の工程配置を確認した。文字入力発注書については、複数レコードの管理画面と、選択した
1レコードをA4縦1ページへ出す印刷物の両方を確認した。

作図発注書について、管理画面と印刷物がほぼ同じ学校別レイアウトで、選択した各学校を1校1ページで
出力することを確認した。原本スキャン発注書については、複数校を1ページへ配置し、管理画面だけに
表示する社内情報を印刷物から除外する構成を確認した。

原本スキャン発注書（解答用紙）は問題等と同じ帳票構造で、A3等の用紙全体をスキャンした場合も
成果物1件を1点として数えることを確認した。
