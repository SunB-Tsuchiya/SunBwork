# WORKLOAD_REBUILD_PLAN1 — 情報出版の作業量分析再設計

作成日: 2026-10-10。管理者確認済み。係数と例外の扱いは試験表示で調整する。

## 目的と範囲

- 予定表の「作業実績の内訳」を入口に、簡易作業、マイジョブ、仕事の会議、残業、進行管理の案件負担を同じ期間（日・週・月）で確認できる分析へ組み直す。
- 情報出版部署で試用し、現行の `WorkloadAnalyzer` の順位と管理者の実感の乖離を照合する。現行分析を直ちに置き換えず、新旧の算式と根拠を区別する。
- 詳細閲覧と暫定係数は既存の Super Admin 試用ゲートを維持する。部署外、グループ会社、非公開案件へのアクセスを広げない。
- 実在する人名・個別の本番集計値はこの文書と試用 Seeder に保存しない。

## 確認済みの業務実態

- A勤務 09:00–17:30、B 08:00–16:30、C 10:00–18:30。昼休憩は個人設定に従う。勤務可能時間は概ね同じ。
- マイジョブは作業後に入力することが多く、イベント時刻も実作業時刻へ直すことが多い。`estimated_hours` の入力は少ない。
- ページ数は新規組版・校正でも案件全体を指すことがあり、実際に触れたページ数とは限らない。ページ数、サイズ、難易度を総合点の係数に使わない。数量は作業の文脈として保持する。
- 仕事の会議は取消されなければ主催者・出席者ともに過去の予定時間を実施時間とみなす。辞退者、実績化コピーの元予定は重複計上しない。
- マイジョブは翌日以降に自動完了するため、`completed` は実施確認の証拠にならない。
- 簡易予定のみ、または必要な結果が未入力の場合は認定実績と暫定点を付けない。「未登録」は「仕事をしていない」と断定しない。
- 残業は加点対象。ただし勤務記録の残業と同じ時間帯に確認できる作業記録がない分は加点せず、未記録の残業時間として別表示する。3時間超の係数は超過分だけ下げる。
- 進行管理では同時に約4件が多い目安。短期・少人数案件を頻繁に回す負担と、長期・多人数案件を管理する負担を両方見せる。副リーダー係数の試案は0.8。完了フラグに依存せず直近14日のチーム活動を案件点の条件とする。
- 登録メンバーは普段から実態に合わせて更新されている。チーム人数にはリーダー・副リーダーが自動で含まれるため、表示では作業メンバー数も分ける。
- 差配・受付、準備・仕様整理、社内改善・システム開発を簡易作業の候補に加える方向。役割に限らず選べるようにする。
- 「ありがとう」は送受双方の件数を試験的に管理者向けの非公開指標として観察し、当面ポイントに加えない。仕様は後段で決める。

## 既存実装から分かった問題

- `WorkloadAnalyzerController` は自己割当を全割当と自己割当で重複集計する経路がある。ページ数がステージ・サイズ・種別・難易度の複数カテゴリに入り、6カテゴリの順位を足した 0–600 点は作業量そのものではない。
- 旧分析のジョブ期間は `desired_end_date`、イベントは実施日時、残業は `work_records.date` を使うため、同じ月の数字が一致しない場合がある。
- `PersonalWorkPoints` は結果文・作業種類・`actual_minutes` が揃う簡易記録だけを合算し、マイジョブや会議を含まない。重複する簡易予定の時間もそのまま合計される。
- `events.interruption_minutes` はイベント同士の重複を差し引くが、簡易記録との重複は対象外。新集計では JST に解決した時間区間の和集合を日別に作り、重複を一回だけ数える。作業種類別に異なる種類が重なる場合の配分は明示する。
- `project_jobs.user_id` は現在のリーダーで編集可能。実際の登録操作をした人の欄はない。作成経路は通常・テンプレート・複製・部署共有・一括作成・ユーザー画面・銀本連携で複数ある。

## 試験スコア案

1. 基本点: 認定された仕事の実施時間 × 10点/時 × 作業種類係数。マイジョブ・簡易結果・会議を統合し、勤務日ごとに休憩と重複を除く。係数は現行の簡易ポイント表を初期値とし、管理画面で算式と内訳を見せる。
2. 残業追加点: 勤務記録の残業時間と、本人の勤務終了後に認定された仕事時間の小さい方に限る。試験初期値は最初の3時間を基本点の0.5倍、超過分を0.2倍にする段階式。境界で総点は下がらない。
3. 案件負担点: 直近14日にチームの仕事が動いた案件へ、試験初期値として活動日あたり0.5点、リーダー1.0／副リーダー0.8、管理者以外の作業メンバー1人につき0.15（最大1.6倍）を掛ける。役割を問わず登録されたリーダー・副リーダーへ付ける。案件数・点数の表示と加点オン／オフを分け、古い未完了案件の滞留で点が増えないようにする。期間配分・上限値は実データで校正する。
4. 案件登録点: 実際の新規登録者に一度だけ付ける。試験初期値は5点/件。通常・テンプレート・複製・部署共有・一括登録・CSV取込は同じ点数にする。連続する定型案件の作成負担を減らすための複製・一括登録を不利に扱わない。システムによる自動生成は実在の登録者がなければ付けない。過去案件の補完値は試験点の内訳で「リーダーから推定」と示し、オン／オフ可能にする。過剰な加点が生じる場合の上限は実データを見て別途相談する。
5. 数量・サイズ・難易度は点数へ加えない。数量は同一作業の参考情報として表示し、ページ/時の個人比較は行わない。

## DB 設計: プロジェクトジョブ登録者

- `project_jobs.created_by_user_id` nullable FK → `users.id` (`nullOnDelete`) を追加。リーダー `user_id` とは別。作成後にリーダーを変更しても登録者は変えない。
- `project_jobs.creator_source` を `recorded_actor` / `legacy_leader` の値で保存する。過去案件は移行時の `user_id` を `created_by_user_id` に補完し、`legacy_leader` とする。`user_id` が null の過去案件は登録者も null のままにする。
- `project_jobs.creation_method` に `manual` / `template` / `clone` / `share` / `bulk` / `csv` / `ginbon` / `legacy` を保存する。登録点は複製・一括取込を含め同じ係数にする。作成方法は内訳と異常値の確認用に残す。
- 新規作成経路は認証済み操作主体を `recorded_actor` として設定する。取り込み等で操作主体がない経路は null とし、実登録者と偽らない。
- 本番 migration は `--force`。バックフィルは対象カラムのみ。既存ユーザーや案件を削除・上書きしない。外部キー、インデックス、再実行安全性を確認する。

## 画面案

- 上段: 記録された作業時間、記録のある日数、暫定点、未記録残業、案件負担を並べる。日・週・月、担当・作業種類フィルタを維持する。
- 左: 暫定点順位。基本点、残業追加点、案件点、登録点を積み上げ、各追加点をオン／オフする。順位の変化を試験する。
- 右: 同じ作業種類の記録時間比較。人数・役割を明示する。
- 下段: 人別の時間帯・作業種類、案件負担（短期の回転／長期の継続／メンバー数）、元の予定・マイジョブへのドリルダウン。欠測と推定値を明示する。
- 「ありがとう」は試験中、公開順位に入れず管理者向け別欄に送受件数を示す。公開範囲は別途決定する。

## 検証方針

- 代表例として、同時間のマイジョブと簡易入力、三重重複、会議主催者/出席者/辞退者、実績化コピー、昼休憩、A/B/C勤務、校正イベントのUTC保存、残業3時間境界を検証する。
- 過去案件の登録者補完、リーダー変更後の登録者不変、新規作成の全経路、複製・共有の扱いを検証する。
- 試験結果は実名を文書に残さず、本番では必要範囲の読み取り専用集計で管理者の実感と照合する。既存 `public/build`・`storage` の他者変更は触らない。
- Vue/JS変更時に `npm run build`。本番デプロイは別途正確な手順を確認する。

## 本番試用後の追加段階：日報作成時の記録確認

- 日報作成・編集画面で、情報出版の試用対象者本人にだけ、当日の作業記録の不足を非強制の案内として表示する。日報の保存条件は変えない。
- 本人の勤務形態と昼休憩から通常勤務枠を求め、既存の試験分析と同じ時間台帳で認定されたジョブ・会議・簡易結果の時間を重複なしで数える。通常勤務枠内の未記録時間が30分以上なら案内する。休憩・勤務枠外の時間で空きを相殺しない。
- 結果文や作業種類が空欄の簡易予定は別件数で案内する。過去のマイジョブ・依頼ジョブは既存の時間記録を集計し、日報への取り込みを強制しない。
- 文面は「記録がない時間は暫定ポイントに反映されません。実際に行った作業をカレンダーで追記できます」とし、作業したと推定して自動加点しない。個人カレンダーの対象日を日表示で開く。既存の日報下書きがある場合の画面遷移では入力内容の保持または確認を維持する。
- 勤務形態が未設定の試用者にはA日程の7時間30分を仮の目安とし、記録時間合計との差で案内する。画面に推定であることを明示する。
- 実装対象は時間集計サービス、日報コントローラー、日報作成・編集の共通案内、個人カレンダーの対象日受け取り。情報出版以外や一般ユーザーへの表示は従来どおり行わない。
- 検証は重複時間、昼休憩、A/B/C勤務枠、30分境界、結果未入力、予定がない日、日付指定のカレンダー遷移を対象にする。本番の実名や個別数値は文書へ保存しない。
