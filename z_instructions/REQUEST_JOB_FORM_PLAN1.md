# 依頼ジョブ新規登録画面の整理・計画 1

更新: 2026-10-17。横断方針と利用者決定は `JOB_EVALUATION_CONTROL1.md` の D13 を優先する。

## 決定と目的

利用者は案件372の通常新規登録画面を確認し、**全項目を常時表示したまま、並びと説明を整理する**と決定した。詳細を開かないと作業種別や概要などを入力できない形にはしない。画面の「割当ユーザー: 未指定」で送信すると本人へ補われる現行挙動は、**未指定のまま送信できず担当者の選択を求める**扱いに置換する。本人宛て依頼は本人を明示的に選べば可能にする。

この工程は情報出版 Super Admin の試用画面で確認する。一般利用者と別部署の Coordinator、既存ジョブの編集・詳細、マイジョブ登録は現行表示と保存経路を維持し、全員公開は別決定とする。

## 2026-10-18 追補: 複数ブロックの一括送信

利用者は、2件目の担当者未指定エラー時に1件目も画面に残ることを確認し、**全件が正しくなければどれも送らず、修正後は複数を一まとまりで送る**と決定した。この未指定エラーではフロントが通信前に止まるため両件未送信。サーバにも、試用対象の新規送信に限り全件の日時・直近重複を保存前に確認し、ジョブと依頼メッセージの保存を一括トランザクションで確定する要件を追加する。非試用経路は既存挙動を維持する。進捗と検証証拠は `REQUEST_JOB_FORM_MANAGER1.md` を参照。

## 提案する画面構成

案件372の画像を基に、1つのジョブブロックを次の順にする。全項目は開閉せず、スクロールで見える。

1. **案件:** クライアントとプロジェクトを読み取り専用で簡潔に表示。
2. **依頼の基本:** ジョブ名、割当ユーザー、締め切りの日付・時刻。割当先の未指定には「担当者を選択」を表示し、送信時にそのブロックへエラーを出す。締め切りは依頼先への期限であり、本人の作業開始・終了時刻ではないと短く説明する。
3. **依頼内容:** 概要、作業ファイル情報。ファイル解析・一覧は従来どおり使える。
4. **作業条件:** 作業種別、ステージ、サイズ、数量・単位、難易度、見積時間。既存値・選択候補・初期値・保存先を変えず、見積時間は必要時に選ぶ欄であることを示す。
5. **操作:** ジョブブロック追加、保存して送信、戻る。複数ブロックなら各ブロックの未指定担当者を個別に示す。

ジョブ名を空にした場合の案件名補完は現行動作として別途検証する。`ProjectJobAssignmentsController::store()` には `assignments.*.title` の必須・任意指定が重複しており、現段階ではこの画面整理の要件へ無断で「ジョブ名必須」を追加しない。実装時に重複の影響を確認し、必要なら別判断にする。

## 実装境界と候補ファイル

- `ProjectJobAssignmentsController::create()` は `PersonalWorkSchedule::available()` と同じ条件で試用表示フラグを返す。`store()` はリクエストの自己申告フラグに頼らずログイン本人を判定し、試用対象が `send_immediately=true` で新規依頼を送るとき、すべての `assignments.*.user_id` を必須として検証する。送信しない下書き経路と既存の会社・案件・担当者の許可条件を維持する。
- `JobAssign/Edit.vue` から新規作成に限って試用フラグを共通 `AssignmentForm.vue` へ渡す。編集、過去データ流用、進行表からの事前入力、複数ブロックを保つ。事前選択済みの担当者はそのまま有効。
- `AssignmentForm.vue` の入力モデルと送信先は共用のまま、試用新規依頼だけ上記の順・説明で描画する。送信時の未指定→本人ID自動補完を試用側で止め、送信前にブロックごとのエラーを示す。サーバ側も送信要求を拒否し、画面側を迂回しても未指定の依頼が送られないようにする。非試用の既存フォームとマイジョブ用フォームへの表示変更は避ける。
- 必要なら新しい小さな表示部品を切り出す。見た目だけを作るために保存処理、関係キー、ファイル情報の別実装を増やさない。
- 管理資料、`CONSOLIDATED_05_calendar_and_jobbox.md`、試用段階の変更履歴を必要に応じて更新する。DB migration は予定しない。

## 検証と反映

1. コードと合成データで、試用対象の未指定1件・複数ブロック中1件未指定が送信されず、明示的な本人選択と他者選択、進行表の事前選択は通ることを確認する。送信しない下書き、非試用の保存経路・既存編集・マイジョブに影響がないことを確認する。本番 sales DB は使わない。
2. 変更PHPの構文、対象 Vue の ESLint、`VITE_APP_BASE_PATH=/members` の Vite ビルド、`git diff --check` を行う。ソースと生成物を今回の差分だけで照合する。
3. さくらへの SSH は `AGENTS.md` に従い正確なコマンドを提示して承認後だけ実行する。試用画面では、全欄の表示、並び、未指定エラー、明示的な本人宛て登録、元の依頼一覧への表示を別々のステップで確認する。未指定エラー確認では保存しない。

## 保留と関連事項

- 別人発信の依頼をマイジョブへ転換する実画面保存は安全な試用候補がなく保留。本人宛て試用依頼では候補選択・転換保存・元依頼の登録済み表示・候補からの消失まで確認済み。
- 全員公開と評価点の判断、ProjectJob と大まかな案件の紐づけはこの工程に含めない。
