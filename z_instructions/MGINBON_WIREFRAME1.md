# MGinbon 画面ワイヤーフレーム 1

作成日: 2026-09-17  
状態: 初稿・一部確認済み

## 1. 画面構成

MGinbonは同じ正規データを、用途別の二つの表で表示する。

```text
MGinbonメニュー
├─ 管理台帳       FileMakerライクな全体管理
├─ 作業用進行表   現物を受け取った本人が作業を検索・自己登録
├─ 自分の作業     JobBox／MyJobBoxのMGinbon絞り込み
├─ 作業レポート   Event由来の担当・時間集計
├─ クライアント共有 読み取り専用URLの発行・プレビュー・失効
└─ データ取込     権限者のみ
```

管理台帳と作業用進行表は別レコードを持たない。担当者、開始日、完了日、状態、実績時間は
同じMGinbon工程作業・Assignment・Eventから取得する。

## 2. 共通ヘッダー

`AppLayout`の既存幅・余白を使い、ページ側に重複ラッパーを置かない。大規模表だけを
ビューポート幅へ拡張し、表内部を横スクロールさせる。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ← MGinbonメニュー    2026年度 銀本制作                                      │
│ [管理台帳] [作業用進行表] [自分の作業] [レポート]                           │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 年度はヘッダー付近のセレクターで切替
- 現在の年度・画面を常に表示
- Coordinator色は緑を主操作に使う
- 一般User画面では青を主操作に使う
- モバイルは全横長表を縮小せず、検索結果をカード表示する

## 3. 管理台帳（FileMakerライク）

### 3.1 目的

進行管理者が、学校・媒体・科目・工程の全体を一画面で把握・補正する。FileMakerのLISTと
入稿チェックは別データではなく、この管理台帳の保存ビューとする。

### 3.2 上部操作

```text
┌─ 2026年度 管理台帳 ──────────────────────────────────────────────────────────┐
│ 表示: [全体▼] [入稿チェック] [初校] [再校] [三校以降] [校了] [外注]          │
│ 学校 [____________]  媒体 [すべて▼] 科目 [すべて▼] 担当 [すべて▼]           │
│ 状態 [進行中▼] α区分 [すべて▼]  □未割当のみ □期限超過                       │
│ 238件表示   [条件をクリア]                         [列設定] [履歴] [取込]      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 初期表示は年度の進行中データ
- フィルターはURLクエリへ保持し、戻る操作で復元
- 入稿チェックは専用の列セットと並び順を持つ
- 管理者用の列設定は表示列だけを変え、工程データ自体を削除しない
- 検索候補は学校名、日能研コード、みくにコード、媒体名を対象にする

### 3.3 一覧本体

```text
┌──────────── sticky ────────────┬──────── 入稿 ────────┬──── 初校 ────┬──── 再校 ────┐
│M/N│学校・媒体│科目│α│分類      │入稿日│文字│作図│scan│OP│初check│出│校正│戻│…        │
├───┼─────────┼──┼─┼─────────┼────┼───┼───┼────┼─┼─────┼─┼───┼─┼─────────┤
│238│学校A 問題│国語│①│男子      │5/27 │社内│ 0 │外 2│A│ 済   │…│B  ✓│…│         │
│   │          │算数│  │          │4/03 │外注│ 7 │内 3│A│ 済   │…│B  ✓│…│         │
│   │          │社会│  │          │4/03 │外注│ 1 │内 0│C│作業中│…│未割当│ │         │
│   │          │理科│  │          │4/03 │外注│ 4 │内 2│C│作業中│…│未割当│ │         │
├───┴─────────┴──┴─┴─────────┴────┴───┴───┴────┴─┴─────┴─┴───┴─┴─────────┤
│ 学校A 解説解答 …                                                                  │
└───────────────────────────────────────────────────────────────────────────────────┘
```

- 左側のコード、学校、媒体、科目をsticky表示
- 工程グループは折りたたみ可能
- 学校→媒体→4科目を視覚的にまとめる
- 担当者名、日付、状態、点数はFileMakerに近い色分けを用いる
- セルには現在値だけでなく、自動入力、手動補正、移行値を区別する小アイコンを表示
- セル選択で右側詳細パネルを開き、履歴・Assignment・Event合計を表示
- 管理者は候補セレクターで補正できるが、作業者の実績を再入力しない
- 保存はセル単位または変更一括保存。競合時は上書きせず最新値を提示

### 3.4 管理セル詳細

```text
┌─ 初校校正・算数 ───────────────────┐
│ 担当        [担当者B ▼]             │
│ 校正入り    2026/04/13  自動         │
│ 校正UP      2026/04/14  自動         │
│ 状態        完了                     │
│ 作業時間    3時間20分（Event 2件）   │
│ Assignment  #1234 [詳細を開く]       │
│                                      │
│ 変更履歴                             │
│ 4/14 完了により校正UPを記録          │
│ 4/13 作業開始により校正入りを記録    │
└──────────────────────────────────────┘
```

自動日付も権限者は訂正可能だが、元値・修正後・修正者・時刻を履歴へ残す。

## 4. 作業用進行表（自己登録）

### 4.1 目的

原稿、校正紙等の現物を受け取った本人が、管理者を介さず該当作業を見つけて登録する。
FileMakerの全列は見せず、「どの現物の、どの作業か」を間違えず選べる情報に絞る。

### 4.2 上部操作

```text
┌─ 作業用進行表 ────────────────────────────────────────────────────────────────┐
│ [空き作業] [自分の作業] [作業中] [完了]                                     │
│ 学校・コード [____________________]  現物/媒体 [すべて▼]  科目 [すべて▼]     │
│ 工程 [校正▼]  段階 [初校▼]                    [検索] [条件をクリア]           │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 初期タブは「空き作業」
- 全対象行を検索可能だが、入力可能なのは空き作業と自分のAssignment
- 手元の現物から識別しやすい学校名、コード、媒体、科目、段階を常時表示
- 完了済みは初期非表示
- OP、校正等の本人の役割を初期フィルターに利用できるが、固定はしない
- 「問題」「解答」の通常制作は4科目一括を初期値とし、α版の解説解答・傾向と対策等は
  選んだ1科目を初期値とする。初期値は年度・商品・媒体別の設定で変更できる

### 4.3 PC一覧

```text
┌──────── sticky ───────────────┬──── 初校 ──────────┬──── 再校 ──────────┐
│コード│学校│媒体│科目│注意      │組版          │校正          │組版          │校正①│校正②│
├────┼───┼───┼──┼─────────┼─────────────┼─────────────┼─────────────┼───┼───┤
│238 │学校A│問題│国語│          │完了 A 2:10   │[自分が担当]  │空き           │空き │空き │
│238 │学校A│問題│算数│図版10点  │完了 A 3:40   │作業中 自分   │空き           │空き │空き │
│238 │学校A│問題│社会│          │作業中 C      │担当済 B      │空き           │空き │空き │
│238 │学校A│問題│理科│          │作業中 C      │担当済 B      │空き           │空き │空き │
│    │     │    │    │          │[4科目に反映] │[4科目に反映] │               │     │     │
└───────────────────────────────────────────────────────────────────────────────┘
```

- 既存`ProgressTable`の多段ヘッダー、sticky列、グループ折りたたみを再利用候補とする
- 空きセルは「自分が担当」ボタンを表示
- 他者の登録済みセルは担当済みとしてロック
- 自分のセルは「カレンダーへ登録」「カレンダーを開く」「詳細」を状態に応じて表示
- 自己登録直前に学校・媒体・科目・工程を確認する小さな確認モーダルを出す
- 登録APIはサーバー側で空きを再確認し、同時登録競合時は後勝ちにしない
- 学校・媒体グループごとに「4科目に反映」を置き、同じ担当・工程を一操作でまとめる
- 個別科目セルから登録する場合も、確認画面で対象科目を追加・解除できる

### 4.4 自己登録確認

```text
┌─ この作業を担当しますか？ ───────────┐
│ 学校      学校A                         │
│ コード    M238 / N2991                  │
│ 媒体      問題                          │
│ 対象科目  ☑国語 ☑算数 ☑社会 ☑理科     │
│ 工程      初校校正                      │
│ 登録単位  4科目を1つの作業として登録   │
│                                      │
│ [キャンセル]          [自分が担当する] │
└──────────────────────────────────────┘
```

確定時にログインユーザーの自己割当Assignmentを一度だけ作成する。4科目を選んでもJobBoxや
カレンダーへ同じ仕事を4件作らず、1つの作業パッケージとして4科目の工程セルへ関連付ける。
担当者・開始・完了・実績時間は一括反映し、科目別進行表では4行すべてに同じ作業状態を表示する。
自己割当は担当確保だけを行い、カレンダーへの作業登録とは区別する。自己割当時点では
`校正入り`を記録しない。

### 4.5 科目一括／個別の切替

```text
問題・初校組版を選択した場合
  対象科目: [✓ 国語] [✓ 算数] [✓ 社会] [✓ 理科]   ← 既定は4科目

α版・解説解答を算数行から選択した場合
  対象科目: [  国語] [✓ 算数] [  社会] [  理科]   ← 既定は選択科目のみ
```

- 4科目セットと科目別のどちらも、最終確認画面のチェックで変更可能
- 存在しない科目、完了済み、他者担当済みの科目は選択不可とし理由を表示
- 一括登録は全対象セルの空きをトランザクション内で再確認し、一部だけ登録しない
- 作業開始後に1科目だけ別担当へ分割する場合は、通常ユーザーの上書きではなく管理者の
  「作業パッケージを分割」操作と履歴で扱う
- 4科目一括作業の実績時間はパッケージ全体へ計上する。根拠なく4分割して科目別時間にしない

### 4.6 作業状態と自動日付

```text
空き
  └─「自分が担当する」→ 担当登録済み
       └─ 既存カレンダーへ作業登録 → Event作成 + 最初の作業日を開始節目に反映
            ├─ 作業が終わらない → 既存の「続き作業」として次回を登録
            │                       source_assignment_idで同じ系列へ接続
            └─ カレンダーで「完了」→ Assignment系列完了 + そのEventの作業日を終了節目に反映
```

校正工程の既定同期:

| 操作 | 管理台帳への反映 |
| --- | --- |
| 自分が担当する | 担当者（選択した全科目） |
| 最初のカレンダー作業登録 | Eventの作業日を対応段階の`校正入り`へ反映（JST日付、選択した全科目） |
| 続き作業を登録 | 工程は進行中のまま。校正UPは未記録 |
| カレンダーで完了 | 完了にしたEventの作業日の`校正UP`＋完了状態（選択した全科目） |

初校校正、校正①、校正②は各自の工程定義に紐づく入り／UPへ反映する。校正①のように
FileMaker側に独立した開始・終了欄がない工程は、既存項目への対応をマッピング表で確定し、
画面に存在しない日付欄を推測追加しない。

「自分が担当する」とカレンダーへの作業登録は別操作とする。現物を受け取っただけ、または後で
作業するために担当を確保しただけでは開始日を入れず、最初にカレンダーへ登録した作業日を
開始節目にする。

続き作業は既存SBWorkの仕様をそのまま使う。新しいAssignmentを`source_assignment_id`で直前の
Assignmentへ接続し、系列のEvent時間を合算する。続き作業がある間はMGinbon工程を完了にせず、
カレンダーの完了処理が既存仕様どおり祖先Assignmentも完了にした時点で、作業パッケージと
対象科目の工程を完了にする。校正UPにはサーバーの処理時刻ではなく、完了対象EventのJST作業日を
用いる。`supersedes_assignment_id`は依頼ジョブの置換用なので使用しない。

### 4.7 既存進行表・カレンダー連動の継承

既存実装では、進行表セルから作成したAssignmentとカレンダーEventを次のように往復連携している。

```text
進行表セル
  → 自己割当Assignment（progress_cell_id／assignment_idで双方向接続）
  → カレンダーEvent（project_job_assignment_idで接続）
  → カレンダー完了
  → Assignment完了・続き作業の祖先Assignment完了
  → 進行表セルの完了表示
```

MGinbonでも同じ接続を利用する。ただし汎用`progress_cells`を正本にせず、MGinbon作業パッケージと
工程タスクをAssignmentへ直接関連付ける。既存のカレンダー完了処理後に、同じトランザクションまたは
専用同期サービスでMGinbonの状態・校正UPを更新する。画面側だけで完了状態を推測しない。

既存の続き作業では祖先Assignmentの`completed`が更新される一方、祖先を参照する
`progress_cells.completed_at`が常に直接更新されるわけではない。ただし既存進行表は関連Assignmentの
`completed`も見て完了表示する。MGinbonでは表示上の間接判定だけに依存せず、系列完了時に
作業パッケージと全対象工程タスクを明示的に完了同期する。

│ 初校校正                    │

横長表の完全再現はせず、検索後の作業候補をカードで表示する。担当後はカレンダーへの作業登録、

## 6. 自分の作業

JobBox／MyJobBoxの既存正規データを利用し、MGinbonだけを絞り込む。

```text
今日の銀本作業
├─ 作業中  学校A／問題／4科目／初校校正      [カレンダーを開く]
├─ 未登録  学校B／解説解答／国語／再校校正② [カレンダーへ登録]
└─ 続き    学校C／問題／4科目／組版修正      [カレンダーを開く]
```

作業タイトルは表示用文字列だけに依存せず、MGinbon工程作業IDを保持する。

## 7. エラー・競合時

- 別ユーザーが先に担当した: 「直前に別の担当者が登録しました」と表示し、セルを再読込
- 対象が管理者により停止された: 自己登録せず理由を表示
- Eventを作れなかった: Assignmentと節目日を中途半端に更新せずロールバック
- 完了後にEvent時刻を修正: 工数を再集計するが、校正UP日は自動変更しない
- 完了取消: 権限と履歴を確認し、校正UPを無条件削除しない
- オフライン・二重クリック: ボタンを処理中無効化し、冪等キーで二重Assignmentを防ぐ

## 8. 初期リリース範囲

初期画面に含める:

- 年度切替
- 管理台帳の全体／入稿チェック／校正段階ビュー
- 学校・コード・媒体・科目・工程・担当・状態フィルター
- 作業用進行表の空き作業検索と自己登録
- JobBox／MyJobBox・カレンダーへの接続
- 最初のカレンダー作業登録による校正入り、カレンダー完了による校正UPの自動反映
- 既存の続き作業チェーンと作業時間合算
- 管理者補正と変更履歴
- 管理台帳、共有進捗、出稿表、文字入力・作図・原本スキャン発注書の印刷専用表示
- ブラウザー印刷およびPDF保存

後段で追加:

- 外注費・単価計算
- 初期版対象外の追加帳票と高度な帳票設定
- 高度な個人・年度比較レポート
- ユーザー別の保存ビュー共有

対象外:

- 原稿PDF、OCR、InDesign、校正PDF等のアップロード・移行・版管理
- 共有サーバー上の制作ファイルそのものの管理

## 9. 確認済み事項

- 作業表の行は媒体×科目とし、複数科目チェックと4科目一括反映を併用する。
- 「自分が担当する」とカレンダーへの作業登録は分離する。
- 最初のカレンダー作業日を校正入り、完了にしたEventの作業日を校正UPとする。
- 複数日にまたがる場合は既存の「続き作業」を使い、MGinbon独自の終了・完了ボタンは作らない。
- 外注先は直接入力せず、社内担当者が入力する。
- みくに出版には、既存進行表のURL共有を基礎とした読み取り専用進捗画面を提供する。
- クライアント共有画面には社員名、校正者名、外注先名を表示しない。

## 10. クライアント共有画面

表示案と公開範囲は`MGINBON_CLIENT_SHARE1.md`を参照する。管理台帳のツールバーに
「共有URL」ボタンを置き、発行済みの場合はプレビュー、URLコピー、再発行、無効化を表示する。
公開画面には社内編集ボタンやナビゲーションを出さず、学校・媒体・科目・工程状態・共有対象日だけを
表示する。
