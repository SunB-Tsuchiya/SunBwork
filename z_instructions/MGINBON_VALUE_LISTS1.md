## 3. 移行ルール

候補値ごとに次を保持する。

- `source_list_name`
- `source_value`
- `target_type`（user / subcontractor / status / execution_type / classification等）
- `target_id`または正規化コード
- `match_status`（unmatched / suggested / confirmed / ignored）
- `confirmed_by`, `confirmed_at`
- `note`

取込時に元値を直接書き換えない。同じ文字列でも値一覧とフィールド文脈を含めて判定する。

## 4. 実装への影響

- 人物セレクターは既存`users`を利用する。
- 外注先セレクターは既存`subcontractors`を利用する。
- 過年度FileMaker名と現行SBWork IDの対応表を持つ。
- 退職者・未登録外注先は文字列を消さず、未解決候補として表示する。
- 状態語を人物として登録しない。
- 将来候補が増えても、FileMaker固定値一覧の再現に縛られない。
