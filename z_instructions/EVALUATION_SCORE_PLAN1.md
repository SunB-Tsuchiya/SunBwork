# 評価点システム完成計画 1

作成: 2026-10-20 JST。現在の優先順位は `JOB_EVALUATION_ROADMAP1.md`、最新決定は `JOB_EVALUATION_CONTROL1.md`。この計画は設計と検証の土台であり、新しい採点式・一般公開・人事査定への自動適用の承認ではない。

## 完成の意味と境界

利用者の第1優先は、入力画面の整理ではなく**評価システムの中身**を完成させること。試用ガイドや画面導線が完成しても、何を点数にするか、職種差・入力漏れ・予定・会議・管理業務の扱い、上長が結果を検証できるかが未決なら本工程は完了しない。

完成ゲートは次の全項目。進捗は `EVALUATION_SCORE_MANAGER1.md` で個別に扱う。

1. 利用者が評価の目的、対象者、比較単位、採点対象、採点対象外、点数に加えない参考指標を確認する。人事の正式判断との境界を明記する。
2. 簡易作業、マイジョブ、依頼ジョブ、仕事の予定・会議・訪問、管理・登録・残業について、未来・取消・私用・非公開・重複・休憩・未指定の条件を定義する。P17 を含む。
3. 時間、工程候補、入力件数、数量、長い単一枠、職種差、管理・登録・残業の係数と上限を、説明できる算式または「点数にしない」として決定する。1日を細かく分割しただけで不当に有利にならないことを確認する。
4. 実装する計算は版と適用開始日を持ち、旧式アーカイブ・既存試用点・新方式の区別、根拠内訳、対象外・欠測・推定値を画面に示す。D14 により過去を一括再採点しない。
5. 会社・部署・private・極秘の閲覧境界、JST/UTC、日別休憩と重複、日・週・月と人別の合計、フィルタの意味を、非破壊の合成例と必要な実画面で確認する。
6. 利用者と上長が、合成例と現在の Super Admin 試用で安全に作れる代表例を使い、点数と業務実態のずれを確認し、採否・修正理由を記録する。一般向け導線の完成や一般公開後の記録を待つことは段階1の前提にしない。P07/R21 の順位異議・約4人レビュー・AI調査案がこの完成ゲートに必要かは利用者が決める。未決のまま「完成」にしない。

## 現在分かっていること

- `WorkloadTrialAnalysis` の試用点は、重複・昼休憩を除いた認定時間と作業種類係数を基本とし、残業・案件登録・案件管理を別に加える。`WorkAnalysis.vue` と `WorkDetailAnalysis.vue` は補助点の表示切替を持つ。時間由来の基本点が大きいため、現行順位を成果や品質とみなせない。
- 仕事の会議・訪問は既存条件で一部算入される一方、通常の `other/private/personal` 予定は対象外。本人が仕事の時間割として使った予定も漏れうる。明示的 private を点数目的で勝手に公開しない。
- 旧6カテゴリ点はページ系の重複と自己割当の二重経路があり、現在のデータから再計算するアーカイブ。新方式の正解値にはしない。
- 2026年9月の対象1人と8月の欠測有無は、データの読み方・ID検索の不具合を切り分けるために確認した。過去全員・全月の検証や新式での一括点数修正には進まない。
- 評価対象外ユーザー、フィルタの「人を絞るだけ」という現行挙動、作業項目設定の部署別係数は、完成前の設計点検事項。設定 UI の別計画を無条件に本工程へ取り込まない。

### E1 のコード予備照合（2026-10-20、GitHub main `530463e12`）

| 現行の処理 | 評価設計で確認する点 |
| --- | --- |
| `WorkloadTrialAnalysis` は `PersonalWorkEntry` の正の分数・許可された作業種類を取り込み、予定イベントが元なら元イベントとの二重算入を避ける。未来の日は除外し、当日の区間は現在時刻で切る。 | 予定の時間を活動とみなす既存決定を維持しつつ、通常予定の業務/私用判定と、取り消した予定の条件を明文化する。 |
| ジョブ連動イベントと固定の会議・外出は対象。会社共有、会議定義、指定された会議・訪問種類は固定予定として判定。その他の通常イベントは対象外。 | P17 の仕事の時間割をどの属性で認定するか。単にイベント種別 `other` をすべて算入しない。 |
| `eventForViewer()` / `entryForViewer()` が `private` と返した記録は分析から除外する。 | **コードからの推論:** 同じ仕事でも閲覧者の可視性でその人の点数が変わり得る。内容を伏せたまま集計値だけ計上するか、権限内の対象を分けるか、点数も伏せるかを利用者と決める。会社・部署・極秘を越える詳細公開はしない。 |
| 分単位で日別休憩を除外し、重複時間は固定予定を優先、同順位の記録は等分する。記録件数は区間に存在する記録キーで、休憩・重複で認定時間0でも件数が増え得る。 | 件数を点数に使う場合は分割有利を防ぐ。時間・件数・工程候補の意味を別表示し、日週月合計を検証する。 |
| 基本点は10点/時×作業種類係数。未指定は既定1.0、会議・外出は0.8。残業は認定作業と重なる時間のみ、案件登録5点/件、案件管理は活動日0.5点×役割・人数係数。 | 初期係数と比較の公平性、管理・定型登録の上限、職種差、未指定の扱いを採点方針として決める。 |
| 詳細画面の担当・作業区分・入力元フィルタは人を選ぶだけで、その人の数値は再計算しない。対象外は `ranking_included` と `workload_tracked`、未設定時は雇用形態の既定値で決まる。 | フィルタ名と数値の意味、対象外設定の操作経路と本人説明を決める。 |

これは読み取り専用の予備照合であり、計算の正しさを全条件で実証した結果ではない。`isFixedAppointment()` 周辺の取り消し判定、設定画面の係数との関係、旧式との接続などを E1 で続けて点検する。実データは読んでいない。

## 利用者と決める設計論点

| 論点 | 確認する選択肢・影響 | 既存の制約 |
| --- | --- | --- |
| 比較の中心 | 時間主導、工程・仕事の節目主導、複数指標併記のどれを主軸とするか。単一順位が必要なら理由と限界を定める | 旧時間点・生件数・ページ数だけで成果を決めない。見える化6:人事参考4は係数でない。 |
| 業務予定と会議 | 仕事/私用の区別をどの入力情報で確かめるか。予定を活動記録とする条件、会議・訪問の出席、取消と非公開をどう扱うか | 各予定の「実施確認」必須化や非公開解除を勝手に加えない。 |
| 仕事の節目・品質 | 本人が残した完了・返却・結果、上長確認、手戻りなどのうち客観的に検証できるものを決める | 自動完了や空欄を品質・怠慢の証拠にしない。新しい必須入力を先に増やさない。 |
| 加点 | 残業、案件登録、管理業務を総点へ加えるか別指標にするか。職種差、定型大量登録、活動案件、上限をどう調整するか | 現行の値は試用初期値。単純な案件数・残業申告をそのまま成果としない。 |
| 欠測・比較対象 | 入力率が低い期間・人、勤怠日がない人、対象外雇用形態をどう表示し比較から外すか | 未入力≠無作業。対象設定の未入力既定値は明示。 |
| 順位のレビュー | 約4人の意見・異議・AI調査機能を評価完成に含めるか、手作業のレビューを先に完成条件とするか | AIが本人評価を自動決定しない。元値と修正理由を追跡する。 |

ここで選択した方針は横断台帳に **確定・提案・保留・置換** を付けて記録する。1回の質問で式を確定させず、具体例と副作用を示して利用者と決める。

## 実施順序

| 工程 | 内容 | できたと判断する証拠 |
| --- | --- | --- |
| E1 現行契約の監査 | 集計元、対象外、権限、算式、設定、画面フィルタ、旧式をコードと資料で突合 | 項目別の「現状／理想／未決」表。実名・本文・個別点数を資料へ残さない。 |
| E2 採点方針の確定 | 上表の論点と代表的な合成例を利用者と確認。必要な上長の見解を収集 | 算式・例外・点数に入れない情報・版開始日・異議処理の範囲を文章で確定。 |
| E3 試用実装 | 集計サービス、必要な設定/表示/APIを、情報出版 Super Admin の既存ゲート内で変更 | 変更範囲と独立した確認結果、他ロールに影響しない証拠。DB変更が必要なら別設計・安全確認。 |
| E4 非破壊検証 | 合成例で日時境界、昼休憩、重複、会議、未来、取消、private、各補助点、対象外、日週月、フィルタを検査 | 期待値と実値の一覧。通常の DB 初期化テストは避け、対象DBを明示した安全な方法に限る。 |
| E5 試用画面・上長照合 | 利用者が1項目ずつ確認。上長が合成例と Super Admin 試用の代表例で職種差と説明可能性を確認 | コード・デプロイ・画面・上長を別々に管理。ずれがあれば E2 へ戻す。一般利用後の長期監視は段階5。 |
| E6 評価完成判定 | E1〜E5 と保留 ID を再点検し、利用者に具体的な仕様と限界を提示 | 利用者の完成判断を記録。一般公開・正式人事利用は別ゲート。 |
