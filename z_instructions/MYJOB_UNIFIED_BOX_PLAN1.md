# マイジョブ入力・BOX統合 設計

更新: 2026-11-02 JST。状態: 設計中・アプリ実装未着手。親計画: USER_WORK_HUB_PLAN1.md。

## 目的と確認済みの範囲

進行管理と作業者の入力負担を減らし、簡易入力を通常のマイジョブ入力へ育てる。カレンダーに置く仕事を本人のBOXで探し、必要時だけ詳細入力や依頼元へ戻れるようにする。旧形式の詳細・添付・続き・依頼からの登録は保持する。会議・外出などの通常予定はBOXへ入れない。

2026-11-02、利用者は統合設計を進めることを了承し「一般ユーザーにはまだ公開したくないので慎重に」と明示した。設計の承認とアプリ実装・限定配備・一般公開を区別する。**現段階でコードや本番の権限を変更しない。** 情報出版の実所属会社/部署のSuperAdmin本人だけの試用を前提にする。分類管理を許可したCoordinator/Leaderまで統合BOXを広げる承認はない。

## 現行実装から確認した事項

| 対象 | 現行と影響 |
| --- | --- |
| 従来BOX | MyProjectJobController::index / MyJobBox/Index.vue。自己割当だけを取得し、通常月は500件・全期間50件のページ単位。実作業日でなくCOALESCE(desired_end_date,created_at)で月を絞る |
| 従来データ | project_job_assignments。sender_id=user_idが自己割当。NULL送信者の本人宛て依頼は受信側。source_assignment_idは続き、supersedes_assignment_idは依頼の置換で別物 |
| 従来の作業日 | eventsと割当の関係。1割当に複数予定を持てるが、現行BOXは先頭予定や締切/登録日中心の表示 |
| 校正 | 旧BOXはproofかつcoordinator_assignment_idのある実行枠を除外する。一方、本人のカレンダーに置く仕事すべてという目的では、校正や依頼由来の予定も読取対象を検討する必要がある |
| 簡易作業 | personal_work_entries。source_event_idがNULLの独立した入力と、旧イベントに結果を添える行を区別する。後者を新しい仕事として重複表示しない |
| 簡易作業の日付 | work_dateはdate:Y-m-d。開始/終了はJSTの時刻。通常予定のeventsと同じテーブルへ複製しない |
| 試用guard | PersonalWorkSchedule::availableは実所属会社のINFO部署SuperAdminだけ。UserWorkHub::availableは一般会社も除外する。canManageBroadProjectsは別権限であり統合BOXに流用しない |
| 既存フォーム | MyJobCreateModalはAssignmentFormと依頼/過去流用の専用pickerを使う。QuickWorkEntryModalは独立作業の入力。これらの保存ルートを一括置換しない |
| 集計 | 日報/試用分析は既存サービスが休憩/重複/実施時刻などを処理する。BOXの表示件数や予定時間を評価点の新たな入力にしない |

## 提案する導線と段階

1. **読取試用を先行。** 新しい統合BOXをSuperAdminだけの確認入口から開けるようにする案。従来BOXのURLと一般Userの通常画面は維持。まずは一覧・検索・元データへの戻りが正しいか確認する。入口の名称/位置と試用実装範囲を利用者へ提示してから実装する。
2. **通常入力を簡単入力へ。** 試用の「マイジョブ作成」は既存QuickWorkEntryModalを使う。作業日と開始/終了、作業名、任意の分類/ProjectJob/仮名、作業区分・種類、任意数量を引き継ぐ。「詳細入力」「依頼から登録」「過去の作業から引用」は既存経路へつなぐ。新たな転換/続きの作り直しはしない。
3. **カレンダー入口を揃える。** BOXでの保存と往復確認後に、試用だけのカレンダー作業入口を同じ通常入力へ揃える案。現行の簡易/詳細の重複入口をいきなり全ロールから削除しない。
4. 一般公開は別の明示判断。データ移行の有無も今回の設計だけで決めない。

単に旧フォームの見出しを変えたり、簡易記録を自己割当へコピーしただけで統合としない。

## 表示データと同一性

初回は新しいDBテーブルを作らず、既存レコードから表示用行を組み立てる案。

| 元 | 内部行キー案 | 表示/操作 |
| --- | --- | --- |
| 独立した簡易記録 | entry:{id} | 既存の簡易編集モーダルで表示/編集。作業日/時刻、作業名、分類経路、数量等 |
| 従来の自己割当 | assignment:{id} | 既存割当詳細/詳細編集へ戻る。予定の有無と複数日表示はQ1/Q2に従う |
| 本人カレンダーの受信/校正/表由来作業 | assignment:{canonical_id} または event:{id} | 元予定/依頼/表へ戻す。旧BOXで除かれた校正実行枠を、その理由を無視して自己割当へ転換しない |
| source_event_id付きの補足記録 | 独立行にしない | 対象イベントへの補足として扱う。元仕事との二重行/二重時間を作らない |

表示上は作業名・作業日/時刻・案件/分類・由来・状態を中心にし、テーブル名/生IDを通常画面へ出さない。由来は必要な「依頼から登録」「進行表」「管理表」「校正」などに留める。

同じ数字IDでも出典が異なれば別レコード。同名/同時刻だけの結合は禁止。続きは異なる記録として残し、source_assignment_idの関係を辿れるようにする。置換済み依頼はsupersedes_assignment_idと本人所有を使って現行マイジョブへ明示対応させる。coordinator_assignment_idは校正の別関係として扱う。具体的な依頼/校正枠のcanonical化と元URLは合成テストで証明するまで確定しない。

従来の割当に紐付く複数eventsは元イベントIDを保持する。日またぎはJSTで日付と表示を処理し、集計のために新しいイベントを保存しない。1つの簡易記録を同名の他記録へ自動集約しない。将来の簡易作業の続き管理は別設計。

## 日付・状態・検索

- 月の基準は、予定済みはカレンダー作業日、簡易作業はwork_dateへ揃える案。締切日を作業日だと見せない。
- 未予定を残す場合の月への所属はQ1回答後に明示する。既存の締切/登録月での検索との違いを設計・画面で説明する。過去の未予定を勝手に全削除/全表示へ切り替えない。
- Q2が1行案なら、複数の作業日/時刻を展開して確認できる。名前一致で違う割当をまとめない。日別案なら行キーにevent_id/対象JST日を足し、仕事件数と予定枠数を混同しない。
- 簡易記録には現在完了フラグがない。「登録済み」と明示的な「完了」を混同しない。時刻が過ぎたという理由でJobBoxの完了や校正依頼を自動更新しない。
- 旧完了非表示/案件別/取引先別の整理は、元の状態を保ちながら統合用表示へ適用する方法を設計する。
- 検索は本人に許された作業名・案件名・分類経路を対象とする案。privateや機密の本文を新しい共通候補へ広げない。
- pagination/件数/月選択肢は両データ源を合わせたものにする。旧500行+簡易別枠を出すだけで統合の並べ替え/ページングを満たしたことにしない。

## 一般公開を防ぐ境界

| 操作 | 必要な境界 |
| --- | --- |
| 試用入口/共有prop | 実SuperAdmin + 実所属INFO + 非一般会社。Coordinator/Leaderの分類管理許可とは分離 |
| 統合一覧GET/検索/全期間 | 同じ試用判定をサーバでも実行、本人ID固定。他人ID/会社ID/部署IDの入力は受け付けない |
| 簡易入力の候補/作成/更新/削除 | 既存write guardを維持。元レコードの本人所有/会社部署を個別確認。privateの本人記録は本人だけ |
| 従来詳細/依頼/校正への戻り | 既存の各詳細・更新の認可を利用。統合一覧に出たことを保存許可の代用にしない |
| 一般Userが新URLへ直接アクセス | 403または既定の非公開応答。メニューを隠すだけで認可済みにしない |
| 一般Userの現行BOX/カレンダー | 既存URL/画面/フォーム/propsを維持。新しい行/ボタンを返さない |
| SuperAdminの別会社コンテキスト | 実所属の試用対象を越える参照へ広げない。現在会社スコープと実所属がずれる場合は停止/非表示を明確に定義 |

## 影響と検証計画

候補ファイルは新しいUnifiedMyJobBoxサービス/専用読取controller/試用Vueページまたは部品、MyProjectJobControllerの試用入口、UserWorkHubの試用判定、QuickWorkEntryModalの呼出文脈、routes/Ziggy、関連テストと独立更新履歴。既存一般向けページを直接丸ごと置換しない。

- 合成SQLiteメモリのみで本人/他人/別会社部署/User/Admin/Coordinator/Leader/SuperAdmin/一般会社/INFO外/別会社コンテキストを検証する。売上DB/本番実記録の複製は使わない。
- 出典別の同じ数字ID、同名別仕事、独立簡易、イベント補足、未予定、複数日、続き、依頼転換、本人宛て依頼、校正旧実行枠を作る。通常予定を除外し、必要な作業予定を落とさない。
- 通常JST/proof UTCをCalculatesEventTimeで扱い、月境界/日またぎ/9時間ずれを検証する。日付列はY-m-dを維持。
- 新しい一覧を読むだけでDB書込がないこと、出典のID/件数/時刻/完了/ファイル/日報関連/依頼登録状態が変わらないことを確認する。
- 入力工程では新規保存/変更/削除、旧詳細/依頼転換/過去引用の往復を確認する。カレンダー・日報・試用分析の重複時間/休憩/時刻を再計算する新ロジックは追加しない。
- JSX/Vue SSR/対象ESLint/PHP構文/members build/manifestと一般Userの従来ルート・propsを確認する。
- 配備前に元版と今回差分を固定し、正確なSSHコマンド承認を得る。migration不要案でも無条件pullや全seedをしない。
